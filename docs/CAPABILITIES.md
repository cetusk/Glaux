# Glaux でできること: AI の能力と作れる曲のジャンル(2026-09-23 時点)

Glaux の AI が何を知覚し・何を操作し・どう表現できるか、そしてそれらと音源・エフェクトで
どのジャンルがどこまで作れるかの整理。機能が増えたら更新すること
(AI の道具を足したら「AI ができること」、音源・エフェクトを足したら「使える道具」とジャンル表)。
前提の環境: 内蔵の音源・エフェクト + SoundFont(FluidR3_GM)+ CLAP プラグイン Surge XT。

---

## 1. AI ができること

AI(チャットのヘッドレス Claude、または外部の MCP クライアント)は MCP ツール 109 個で Glaux を操作する。
すべての編集は人間と同じ履歴に残り、取り消せる。

### 1.1 感覚(何を知覚できるか)

| 感覚 | ツール | 分かること |
|---|---|---|
| **楽譜を読む** | get_project | 全トラック・クリップ・ノート・音源とつまみ・テンポ・拍子・曲の構成(セクション)。include_notes: false で構造だけ俯瞰 |
| **音を聴く(曲・ミックス)** | analyze_audio | オフラインで鳴らして、ラウドネス(統合・短期の推移・LRA)・ピーク・True Peak・ダイナミクス・帯域バランス・明るさ・発音の数・ステレオの広がりと位相。per_track でトラックごとのバランスと、トラック間の周波数のかぶり(マスキング: どの帯域で何が何を覆っているか) |
| **言葉で音を追い込む** | refine_by_words | 「暖かく」「刺さらないように」のような注文を音色語(CLAP の辞書)に置き換え、トラックの内蔵エフェクトのつまみを、実際に鳴らして聴き比べながら言葉に近づく方へ動かす。音量はそろえて比べるので、大きくするだけでは近づかない(音色語のモデルが必要) |
| **マスタリング・参照曲に寄せる** | master_mix | 曲を描き出して、マスターの最後に足す EQ・コンプ・(幅)・リミッタのつまみを決める。参照曲があればその音色の釣り合い(1/3 オクターブ)・広がり・音量に寄せ、無ければ出っ張り・へこみを均して配信先の音量(-14 LUFS など)にする。True Peak は -1 以下。1 回の undo で戻せる |
| **編集の前後を聴き比べる** | compare_mix | チェックポイント・履歴の地点と今を同じ条件で鳴らして比べる。音量の差(と、そろえるための補正量)を分けて示し、音色の釣り合い(オクターブ帯域ごと)・広がり・ダイナミクスは音量に左右されない指標で比べる。人の耳は大きい方を良いと感じるので、その錯覚を避ける |
| **音色を聴き分ける(1 音)** | analyze_sound | サンプル・音声クリップ・トラックの 1 音を細かく数値化: 包絡(立ち上がり・減衰・持続・余韻)、音程(学習済みモデル SwiftF0 で推定。ずれ・しゃくり・ビブラート)、スペクトル(明るさとその推移=フィルタの開閉、ノイズっぽさ)、倍音(奇数/偶数・減り方・金属っぽさ・波形の推定)、言葉での要約。さらに学習済みモデル CLAP で「聴いた」印象を言葉で(何の楽器らしいか・明るさ・質感・雰囲気。追加モデルの取得が必要) |
| **音を聴き比べる** | compare_sounds | 2 つの音(サンプル・クリップ・トラックの 1 音)の距離(音色・音量の時間変化)と、明るさ・立ち上がり・減衰・長さ・ノイズ・倍音・音程の違い、寄せ方の手がかり、CLAP での印象の近さ |
| **拍を感じる(音声)** | analyze_beats | 取り込んだ曲・ループ・録音のテンポ(小数まで)・拍子・小節頭の位置・テンポの揺れ(打ち込みか人の演奏か)。テンポ追従の元テンポに使える |
| **参考曲の構成を読む(音声)** | analyze_reference | 小節ごとの和音の色・音色・音量の似かた(自己類似行列とノベルティ)から区間の境目と繰り返し(A・B・C)を出し、イントロ・A メロ・B メロ・サビ・C メロ・アウトロを推し量る。区間ごとの音量の差・明るさ・コードの目安・キー・テンポ。構成と起伏だけを写し、メロディや音は写さない |
| **音楽理論の目** | analyze_harmony | キーと、小節ごとのコード進行(推定値。確からしさ付き) |
| **リズム感** | analyze_rhythm | スウィング比(ストレート / シャッフル)・グリッド(2 分割 / 3 連)・シンコペーション・ずれの大きさ(機械的 / 人間的)・密度 |
| **つまみの意味** | list_params | 内蔵の音源・エフェクトのつまみ全部に、範囲と「聴感上の効果」の説明が付く。CLAP プラグインのつまみは名前で絞り込み、画面上の表示(例「-48.00 dB」)も読める |
| **曲の計画書** | set_song_plan | 区間ごとの小節数・盛り上がり(0〜10)・鳴らすトラック・役割を書くと、区間のマーカーを置き、曲の長さ(秒)を返す。点検が計画と実際を突き合わせる |
| **音とミックスの点検** | critique_mix | トラックごとにソロで描き出して測り、低域の左右の広がり・音の頭と終わりのクリック(位置は小節:拍)・キックとベースの低域のぶつかり・True Peak・モノにしたときの減り・2〜5kHz の刺さり・200〜400Hz のこもり・トラックどうしのかぶり・中央に重なったユニゾン・動かない長い音・空間の無さを、直し方の道具と一緒に返す |
| **言葉から音色** | design_sound | 「暗くて太いベース、少し揺れる」のような文から内蔵音源のパッチを作る。言葉の対応表(役割 12 種と、明るさ・太さ・動き・広がり・空間・アタック・歪みの向き。「少し・とても」「〜なし」、ローファイ・8bit・息っぽい)で作り、CLAP のモデルがあれば言葉との近さを測って追い込む(言葉の向きは覆さない)。どのつまみを変えたかを説明する |
| **音色の変種** | mutate_sound | 今の音色(内蔵の音源)のつまみを少しずつ揺らした変種を作り、1 音ずつ描き出して測って互いに最も違うものを選び、違い(明るい・立ち上がりが速い・よく伸びる・ざらつく・広い・揺れが多い…)を言葉で添える。番号で当てて、もう一度呼ぶと次の世代 |
| **共通の大きなつまみ** | set_character | どの音色にも効く 7 つのつまみ(明るさ・太さ・動き・広がり・空間・アタック・歪み、0〜100、50 = 作ったときの音)。音源・エフェクトの種類ごとにつまみへ割り当てる(CLAP 音源はつまみの名前から推定)。中身はマクロなのでオートメーションで動かせる |
| **定番の手順** | apply_recipe | センドのリバーブ(返りの帯域とプリディレイ込み)・テンポに合わせたディレイ・キックとベースのすみ分け(サイドチェインかダイナミック EQ)・ボーカルのチェーン・広げたスーパーソー・ドラムの並列コンプを 1 回で組む(1 回の undo で戻る) |
| **編曲の点検** | critique_arrangement | 楽譜から「機械的すぎる(16 分の格子どおり・強弱が平ら)」「動きが無い(オートメーションが無い)」「変化が無い(同じ型のまま区間をまたぐ)」「区間ごとの起伏が小さい・抜き差しが無い」「低い音域の濁り」「マスタリングをしていない」「曲の計画書と違う」を見つけ、直し方(使う道具)と一緒に返す。トラックごと・区間ごとの数値(区間の盛り上がり 0〜10 など)も。完了を報告する前に使う |
| **人間の操作を知る** | get_history | 誰が(人間 / AI)何をしたか。チャットでは前回からの人間の編集が自動で伝わる |
| **いま見ている場所** | UI からの文脈 | 選択した小節範囲・ピアノロールで開いているクリップ・音作り中のトラックが指示に自動で添えられる |

### 1.2 手(何を操作できるか)

| 分野 | ツール | できること |
|---|---|---|
| **作曲** | apply_commands | トラック・クリップ・ノートの追加・変更・削除、クリップの分割・ループ化、テンポ・拍子(途中変更も。7/8 の 2+2+3 のような拍のまとまりも)、曲名、構成マーカー(Aメロ・サビ等)。ノートは「5:1 1/8 E4 v96」のような短い書き方(小節:拍・長さ・音名、+ で和音)でも送れる |
| **変拍子** | change_meter / write_polyrhythm / write_polymeter / set_meter_feel / metric_modulation / hemiola / write_tihai / shift_notes(wrap_in_bar) | 1 小節だけ拍を足す・抜く(サビ前の 2/4 など。後ろはずらす)、ポリリズム(3:2・4:3・5:4)、ポリメーター(周期の違う型・ユークリッドリズム E(5,16))、アクサクの長い拍の比(1.5 からずらす)、音価の読み替えでテンポを変える(3 連の 8 分 = 8 分)、ヘミオラ(3 拍子の 2 小節を 2 拍ずつに)、ティハイ(同じ句を 3 回で小節の頭に着地)、拍の置き換え(小節の中で回す)。ドラム・和音・ベース・旋律・グルーブ・スウィングの道具は拍のまとまりに沿う |
| **ノートの一括編集** | transpose_notes / shift_notes / quantize_notes / swing_notes / scale_velocity | 移調、時間移動、クオンタイズ、スウィング(ハネ・シャッフル)、強弱の一括調整 |
| **アルペジオ** | write_arpeggio | コード進行(write_chords と同じ書き方)を、Live のアルペジエーターの 18 の型(上り・下り・上り下り・内から外・一番上を挟む・一番下を挟む・役割の順・和音まとめて・でたらめ 3 種など)で、刻み(16 分・3 連・付点)・オクターブの広げ方・音の長さ・1 回りごとの移調で鳴らす。強弱の列とリズムの列は音の並びと別の長さで回る(ポリメーター) |
| **コード進行から伴奏** | write_chords | コード記号(Am7・G7(b9)・C/E)かローマ数字(キーを指定。IVmaj7・V7/V)の進行を、積み方(密集・開離・ドロップ 2/3・スプレッド・シェル・ルートレス)と音域に沿って、声部の動きが最も小さく平行 5 度・8 度を避ける並びで積み、リズムの型(伸ばし・8 分・裏拍・チャールストン・自由な文字列)で置く |
| **進行の候補** | suggest_progression | ジャンルと雰囲気から定番の進行(王道進行・丸サ進行・カノン・小室進行・ii–V–I・ブルース・短調の EDM 進行など)を選び、キーに当てたコード名で返す |
| **区間のつなぎ** | write_transition | ドロップ・サビの直前を全トラック無音にし(かかる音は手前で切る)、区切りでちょうど鳴り終わるリバースクラッシュ・スネアのロール・区切りのクラッシュを置く |
| **ドラムの型** | write_drums | ジャンルの型(ハウス・テクノ・トラップ・ブームバップ・ローファイ・ファンク・ロック・ポップ・ドラムンベース・ディスコ・レゲトン・ハーフタイム・2 ステップ)を、音の多さ・小節ごとの変化・区切りのフィル(スネア / タム)とクラッシュ・ビルドのスネアロール・直前の無音と一緒に置く。キック・スネア・ハットなどを楽器ごとの別トラックに分けて置くこともできる(parts) |
| **ベースライン** | write_bassline | コード進行から、型(根音の伸ばし・8 分・裏拍・オクターブ・3-3-2・808 の滑り・ファンク・ウォーキング)か度数入りの文字列でベースを置く。根音のオクターブは進行全体で滑らかに選び、次の和音へ近づく経過音やキックと同じ位置に合わせることもできる |
| **旋律の点検** | critique_melody | 旋律の「センス」のうち数えられる性質を測り、直し方と一緒に返す: 跳躍の多さと跳躍の後の戻り・区間の中の音域・最高音が山の区間で初めて出るか・強拍の和音の音・リズムの単調さ・動機の反復率・食い・句と息継ぎ・句の終わりの伸び・音ごとの驚き(Temperley の式)。ジャンルごとのしきい値、0〜100 の点数 |
| **旋律の構造** | analyze_melody | 旋律を区間 → 句 → 骨格の層に読み返す: 最短経路による旋律の還元(AMRA)の骨格、句の区切りと繰り返しの地図(A・A′・B)、区間ごとの音域・密度の曲線とリズムの似かた、句の終わりの伸びと主音。粒度付きの指摘(同じリズムの輪郭が続く・音域が動かない・区間に対比が無い) |
| **動機の展開** | develop_motif | 短い動機を、形式の型(sentence・period・AABA・call & response・loop)か操作の並びで展開する。繰り返しの 2 回目以降はリズムも変える(割る・付点・まとめる・休む・拡大・縮小・ずらす)。強拍を和音に合わせ、問いは開いて答えは主音で閉じて伸ばし、最高音は全体の 60〜75% の位置に 1 回、強拍の一部を 8 分前へ食わせる。展開した旋律の点検の結果も返す |
| **旋律を作る** | write_melody | 役割(A メロ・B メロ・サビ・フック・リード)とジャンル(ポップ・EDM・トラップ・ローファイ・ジャズ・ファンク)から、ジャンルのリズムの型(1 小節目は動き、2 小節目は伸ばして息継ぎ)と輪郭(弧・上行・下行・谷・同じ音のフック)で動機を作り、develop_motif と同じ手順で展開する。複数の案を作って旋律の点検の点数で選び、2 番目の案を同じ音色の複製トラックに置いて聴き比べることもできる。動機のリズムは固定もできる |
| **旋律の表情** | pitch_gesture / set_vibrato | 音程の表情(しゃくり・スクープ・プロップ・スライドイン・ベンド・フォール・ドイト・こぶし・シェイク)を、句の頭・句の終わり・上への跳躍・長い音の規則か音の指定で付ける(ピッチカーブ 16 点・区間ごとの曲がり方に展開)。ビブラートは速さ・深さ・始まり・フェードイン/アウト・終わりの速さを音ごとに持ち、歌・弦・ギター・管・シンセの型から選べる(内蔵音源と CLAP 音源で同じ揺れ) |
| **装飾音・旋律のリード** | add_ornament / melody_lead | 前打音(短・長)・モルデント・ターン・トリル・シュライファーを、音階の隣の音か半音で(装飾は 8 分の 20%、トリルは 1 秒 10 音の目安。短前打音は前の音から時間を取る)。旋律を伴奏より 20ms ほど先に鳴らす(和音はいちばん上の音だけ、強さの差に比例させることもできる) |
| **音の中の強弱・明るさ** | note_dynamics | 1 音の中の音量と明るさの動き(ふくらむ・消える・スフォルツァンド・フォルテピアノ・音量の揺れ・暗くから開く・明るくから閉じる)。ノートの音量・明るさの曲線として持ち、内蔵音源は出口で、CLAP 音源には 1 音ごとの VOLUME・BRIGHTNESS として送る。フォール・ドイトは音量も一緒に下げる |
| **ストローク・ルーディメント** | strum_chord / drum_rudiment | 和音を少しずつずらして鳴らす(ギター: 拍の頭は下げ・裏は上げ、拍の手前に出し、後の弦ほど弱く。上げは上の 4 本だけを弱く速い振りで鳴らしてダウンとアップの差を出す / ピアノのばらし / ハープ)。ドラムのフラム・ドラッグ・ラフ・ラチェット・ロール・ハットの連打・バズロール(刻み・強さの傾き・人間の限界の警告) |
| **切り方・トレモロ・グリッサンド** | articulate_notes / tremolo / glissando | 次の音までの間隔で音の長さをそろえる(レガート・テヌート・ポルタート・スタッカート。同じ音の連打は少し空ける。レガートは奏法 legato も付けられる)。同じ音・2 音交互・和音のトレモロ(刻みか 1 秒あたりの回数)。音を並べるグリッサンド(キーの音階・白鍵・黒鍵・半音)と音程の曲線で滑らかにつなぐグリッサンド |
| **条件付きの発音** | set_note_condition | ループの繰り返しに変化を付ける: 鳴る確率と「b 回に 1 回・a 回目だけ」(4 小節目だけのフィルなど)。ノートとループの回から決まるので再生と書き出しで同じ |
| **サステインペダル** | sustain_pedal | ピアノのペダルを音の長さに焼き込む(和音が変わる所・小節ごとに踏み替え、区切りの少し手前まで伸ばす) |
| **句の呼吸** | shape_phrase / swing_notes(jazz_tempo) | 句の半ばへ少し速く、終わりをリタルダンドで緩める(Friberg らの式)テンポの変化を書き、強さも連動させる。ジャズのハネの量をテンポから決める(短い方の音 = max(100ms, 3 連)) |
| **譜面の書き出し** | export_musicxml | MusicXML(MuseScore・Dorico などで開ける)。拍のまとまり(2+2+3)・テンポ・調号も入る。32 分の格子にそろえ、1 パート 1 声部(和音・タイ) |
| **音源の重ね(層)** | set_layer | 1 トラックに音源を最大 4 層(本体 + 3)重ねる。層ごとに音源(内蔵・SoundFont・SFZ・音色のプリセットの音源部分)、音量・パン・移調、鳴らす鍵盤とベロシティの範囲。キックにサブ、スーパーソウに 1 オクターブ下のサイン、強く弾いたときだけ鳴る層など |
| **マクロ** | set_macro | 1 トラックにマクロを 8 個まで。1 つの値(0〜1)で複数のつまみ(内蔵の音源・エフェクトのつまみ、トラックの音量・パン)を最小〜最大・曲線付きで動かす。「明るさ」「厚み」のような意味の取っ手になり、`macro/N` の値とオートメーションで動かせる(再生データを作るときに焼き込む)。音色のプリセットは層とマクロも持つ |
| **変調(LFO)** | modulate | トラックに LFO を 8 個まで付け、内蔵の音源・エフェクトのつまみ(カットオフ・ウェーブテーブルの位置・エフェクトのミックスなど)をテンポに合わせた周期か Hz で揺らす(sine / triangle / square / saw / random)。同じつまみのオートメーションがあればその値を中心に揺らす |
| **変調・質感のエフェクト** | add_effect | クリッパー(ソフト・ハード・折り返し)、ビットクラッシュ、トレモロ / オートパン、フェイザー、フランジャー、トランスゲート(16 分の型)、動くフィルター(テンポ同期の LFO と音量への追従)、音量シェイパー(サイドチェイン無しのポンピング)。テンポに合わせるものは曲の位置に同期する。ディレイのダッキング、ゲートリバーブ |
| **旋律の変形** | transform_notes | 反行・逆行・音階の度数での移調・反復進行(ゼクエンツ)・拡大縮小を、キーに沿って正確に |

### 1.3 表現(どんな演奏ができるか)

**奏法(ノートごとに付ける)** — 楽器によって効くものが違う(効かない組み合わせは無視される)

| 奏法 | subtractive / fm / wavetable | drum | pluck | sampler / sf2 | CLAP | 効果 |
|---|---|---|---|---|---|---|
| パームミュート | ○(こもった刻み) | − | ◎(本命) | − | △(短く弱く) | 減衰を速く・暗く |
| スタッカート | ○ | − | ○ | ○ | ○ | 音価を半分に |
| アクセント | ○ | ○ | ○ | ○ | ○(強く) | 強く(楽器により明るく) |
| ビブラート | ○ | − | ○ | ○ | ○ | 後半に深くなる揺れ(ノートの vibrato で速さ・深さ・始まり・フェードを音ごとに決められる) |
| ベンド | ○ | − | ◎(チョーキング) | ○ | ○ | 全音下から滑り上がる |
| レガート | ◎ | − | ○(ハンマリング) | ○ | △(重ねて送る) | 直前の音から弾き直さずになめらかにつなぐ |
| ポルタメント | ◎ | − | ○(スライド) | ○ | ○ | レガート + 直前の音程から滑らせる(フレーズの頭は全音下から滑り込む。滑る時間はトラックごと・ノートごとに変えられる) |

CLAP の列: ビブラート・ベンドは内蔵音源と同じ形の音程変化を 1 音ごとの表現として送る(Surge XT など CLAP のノート表現に
対応したプラグイン。MIDI だけのプラグインには届かない)。アクセントはベロシティを上げ、パームミュートは短く弱く鳴らして近づける
(音色をこもらせるのはプラグイン側のつまみ・オートメーションで)。

**そのほかの表現**

- **ピッチカーブ**: 1 音ごとに音程を自由な曲線で動かす(しゃくり・ポルタメント・ダイブ・808 のグライド)。
  内蔵音源にも CLAP 音源(1 音だけの音程変化として)にも届く
- **ベロシティ**: 1 音ごとの強さ。楽器によって音量だけでなく明るさも変わる
- **タイミングのゆらぎ**: apply_groove でジャンルの型(楽器ごとのずれと強弱)・前ノリ後ノリ・小さな揺れを付ける。
  analyze_rhythm で既存のノリを測り、swing_notes でまとめてハネを掛けられる(UI はピアノロールの「スウィング」)
- **ループ**: 1〜2 小節のパターンを繰り返す(ドラム・リフ)
- **ダイナミクスの流れ**: 音量・音色のオートメーションで、ビルドアップや展開を作る

### 1.4 AI にまだできないこと

- **生の音を聴くこと**: analyze_audio / analyze_sound は数値と言葉の要約(CLAP の印象語も目安)。「この音が気持ちいいか」は直接は分からない(人間の感想が頼り)
- **どんな音でもそっくりに作ること**: 内蔵シンセの自動合わせはシンセらしい単音なら「よく似ている」まで届くが、
  生楽器・複雑な音は「似ている部分がある」止まり。プリセット検索と人間の耳での仕上げが前提
- **演奏をリアルタイムに聴くこと**: 人間の録音・MIDI 入力は取り込めるが、弾いている最中に反応はできない
- **プラグインが公開していない設定**: 例えば Surge XT の LFO のテンポ同期・モジュレーションの割り当て。
  プリセットには入っているので「それらしいプリセットを探す」で代用する。細かい調整は人間がプラグインの画面で行う
- **歌声を作ること**: 歌声合成・ボーカルの音程補正は無い(鼻歌の譜起こしはできる)
- **MIDI の CC(モジュレーションホイール等)の打ち込み**: 時間変化はオートメーションで代用する

## 4. まとめ

- **得意なのはシンセ主体の電子音楽**。Surge + sidechain + オートメーションがそろい、AI がプリセット探しから
  つまみの微調整まで担える。
- **ポップス・ロック・劇伴は「作れるが音質は GM 音源なり」**。ピアノ専用・ストリングス専用などの高品質な
  SoundFont に替えると一段上がる。
- **生音・歌もの中心は苦手**。ボーカル向けの処理(音程補正・テイク編集)が無い。
- **AI の強みは「楽譜・理論・リズム・音の数値」を同時に見られること**。弱みは音の質感を直接は聴けないことなので、
  音色の最終判断は人間の耳で行い、AI には「もっと明るく」「埋もれている」のように感想で伝えるのが効く。

## 5. 伸ばすと効果が大きいもの(優先順)

1. **似た音を作る力のさらなる強化**: ウェーブテーブル音源、歪み・コーラス込みの自動合わせ、自動選択時の探索時間の配分の改善。
   これまでの調査と結果は [`AUDIO_ANALYSIS_RESEARCH.md`](AUDIO_ANALYSIS_RESEARCH.md)
2. **作曲・演奏の表情・音作りを本格的にする**: 曲の骨格を作る道具(コード進行からの伴奏・ベース・ドラムの型・曲の計画書)、
   ノートごとの表情の曲線、内蔵シンセの変調とレイヤー、良質な無料音源(SFZ)。段階ごとに進めており、調査と計画・進み具合は
   [`MUSIC_EXPRESSION_RESEARCH.md`](MUSIC_EXPRESSION_RESEARCH.md)
