# 構造・階層を意識した旋律(記号音楽)生成の研究 ― 調査レポート(2026-09-30)

対象: Glaux の `write_melody` を「区間の波の計画 → 句の骨格 → 肉付け」の上から下への生成と、粒度を上下する改稿のループに作り替えるための下調べ。

## 凡例

- **[一次・本文]**: 論文の本文(PDF)を読んで確かめた。数値は本文の表から写した。
- **[一次・要旨]**: 要旨(abstract)または著者の公式ページだけを確かめた。
- **[一次・コード]**: 著者が公開したコードを読んで確かめた。
- **[二次]**: 他の論文による紹介など、又聞き。
- **[推測]**: 私の解釈や、Glaux に当てはめたときの見立て。

主観評価の数値は、断りが無ければ 5 段階の平均(MOS)。評価者の数が 10〜60 人程度の小さな試験が多いので、差は「傾向」として読む。

## 0. 要旨(先に結論)

1. **「骨格 → 肉付け」の二段にすると、人の評価は一貫して上がる。** WuYun(+0.51 点)、MusicFrameworks、Compose & Embellish(構造 +1.03 点)、MELONS(総合 +0.9〜1.1 点)、MeloForm(+0.5〜0.9 点)、TeleMelody(+1.1〜1.4 点)、Whole-song(ICLR 2024)。ただし**どれも人の作品には届かない**。差はだいたい 0.5〜1.2 点残る。
2. **上位の計画は機械が作っても人の計画と同じくらい良い。足りないのは下の層(肉付け)。** 生成した骨格・構造グラフ・基本旋律と、実曲から取り出したものとで、最終の評価はほぼ同じだった(WuYun-RS 3.00 と RRS 3.02、MELONS 3.20 と 3.22、MusicFrameworks の "1 vs 2")。WuYun の著者も「骨格を上手に装飾するのは人でも難しい」と書いている。
3. **骨格の選び方には「ちょうどよい量」と「柔らかさ」が要る。** WuYun の比較では、骨格の音が全体の 14% だと少なすぎ、63% だと多すぎ、**リズムの骨格(約 34%)が最良**だった。**強拍だけの骨格は硬く、ランダムに選んだ骨格より悪い。** 強拍・長い音・シンコペーションを混ぜた骨格が良い。
4. **骨格の取り出しは、学習なしの規則と探索でできる。** 最短経路による旋律の還元(Wang ら ISMIR 2025)は、辺の費用(同音 0.1、2 度 0.3、同じ和音の分散 1.5 …)と音の重要度(強拍・長さ・和音の音)だけで動く。Glaux にそのまま移せる。GTTM のタイムスパン木(浜中ら)を使えば、木を途中で切って抽象化し、差分の枝で音を増減させる操作(meet / join)もできる。
5. **計画の表現で効いたもの**は次のとおり。
   - 句の平均音高と音域幅(MeloForm の `AVGPITCH` / `SPAN` の指示を 92.5% / 99.7% の精度で守れた)
   - 小節ごとの音の密度と平均音高(FIGARO)
   - 小節ごとのリズムの型の名札と複雑さ(MusicFrameworks)
   - 句の残り小節数(Whole-song)
   - 終止の種類(TeleMelody)
   - 緊張の曲線(MorpheuS)

   ただし**緊張の曲線だけを合わせる探索は、句の構造と無関係に終止を置いてしまう**(MorpheuS への専門家の指摘)。
6. **句と区間は、音高・和音・音の長さの分布をはっきり変える**(Dai ら 2020・2022)。
   - 句の終わりは長い音。全音符以上の音の 72% は「区間の最後の句」の終わりにあり、「区間の途中の句」の終わりには 6.4% しか無い。
   - 区間の途中の句は V、区間の終わりは I で終わりやすい。
   - 旋律の主音は、句の終わりで 35%、他の位置で約 20%。
   - 深層モデル(VAE)の出力は、どの位置でも主音が 20〜21% で平らだった。

   **「位置による違いが無い」ことが AI らしさの測れる兆候の一つ**になる [推測]。
7. **改稿のループ**も研究がある。
   - Coconet: 一部を消して書き直す Gibbs 法が、一度で書く方法より人の評価で良かった。
   - MeloForm: 似た句をまとめて句ごとに繰り返し改稿する。
   - WuYun: 段の間で骨格を人が直せる。
   - MusicFrameworks: 100 案を作って選び、輪郭の似かたに 0.7 のしきい値を掛ける。

   総説(Bhandari & Colton 2024)も、次の研究課題に「止まって考えて直す(pause-think-refine)」枠組みを挙げている。

## 1. 骨格(還元)から肉付けへ

### 1-1. WuYun: 骨格で導く階層的な旋律生成 [一次・本文]

- 出典: Kejun Zhang, Xinda Wu, Tieyao Zhang, Zhijie Huang, Xu Tan, Qihao Liang, Songruoyao Wu, Lingyun Sun. "WuYun: Exploring hierarchical skeleton-guided melody generation using knowledge-enhanced deep learning." arXiv:2301.04488(2023)。https://arxiv.org/abs/2301.04488 、コード https://github.com/NEXTLab-ZJU/wuyun
- **要点**: Schenker と GTTM の「構造と延長(structure and prolongation)」の考え方に従い、生成を 2 段に分ける。
  1. 骨格を作る: Transformer-XL が骨格の音だけを生成する。
  2. 骨格を埋める: エンコーダ・デコーダが、骨格の音を残したまま間の装飾音を埋める。
- **骨格の取り出し(規則)**
  - **リズムの骨格**: 小節ごとに次の 3 種を骨格の音とする。
    - 拍節のアクセント(強拍の音)
    - 強拍に乗った長い音(agogic accent)
    - シンコペーションに乗った長い音
  - 骨格の音が続くときは、アクセントの強さで 1 つに絞る。強拍とシンコペーションは両立しない。
  - **調の骨格**: リズムの骨格の位置で区間を切る。2〜3 音の「リズムの細胞」ごとに、螺旋配列(spiral array)で調からの距離(緊張)を計算し、**最も緊張の低い音**を選ぶ。
- **中間表現**: 骨格の音の列(位置・高さ・長さ・強さを 1 語にまとめた複合トークン。和音の記号は骨格には入れない)。データは C3〜C5 に移し、ハ長調かイ短調にそろえる。
- **評価 1(骨格の種類の比較)**: 30 人(うち専門家 15 人)が 90 曲を聴いた。
  - 骨格の音の割合は、強拍だけ 32.8%、長い音だけ 27.4%、**リズム 33.8%**、調 43.2%、積(両方に入る音)14.2%、和 62.8%、ランダム 25 / 50 / 75%。
  - **リズムの骨格が 5 項目すべてで最良**、次が調の骨格。
  - 強拍だけ・長い音だけの骨格は、豊かさ・期待・総合でランダムの骨格にも負けた。**「一種類のアクセントだけの硬い骨格は質を下げる」**。
  - 積(14.2%)は最悪で、少なすぎて導けない。和(62.8%)も落ちた。**割合を増やすと評価は一度上がってから下がる。**
  - 調の骨格は音名が C・D・E に偏り、これも硬さの原因になった。
- **評価 2(他の手法との比較)**: 13 人(うち専門家 6 人)、5 段階。最初の 4 小節を手がかりに最大 28 小節を生成。

  | 手法 | リズム | 豊かさ | 構造 | 期待 | 総合 |
  |---|---|---|---|---|---|
  | Music Transformer | 2.52 | 2.34 | 2.28 | 2.47 | 2.25 |
  | CP Transformer | 2.77 | 2.72 | 2.74 | 2.70 | 2.65 |
  | MELONS | 2.84 | 2.68 | 2.75 | 2.67 | 2.71 |
  | **WuYun-RS**(生成した骨格) | 3.13 | 3.07 | 3.13 | 3.02 | 3.00 |
  | WuYun-RRS(実曲の骨格) | 3.20 | 3.11 | 3.15 | 3.00 | 3.02 |
  | 人 | 3.54 | 3.65 | 3.68 | 3.55 | 3.57 |

  - 骨格を使わない同じ表現の単段モデル(MeMIDI)の総合は 2.42 で、同じ条件のまま骨格を足すと +0.58。
- **限界(著者)**
  - 実曲の骨格を与えても、完成した旋律は人の作品に遠い。**肉付けが難しい**。
  - リズムと音高を組み合わせた骨格はまだ作れていない。積や和では悪くなった。
  - 客観指標(特徴の分布の重なり)は、構造や音楽性の良さと一致しなかった(PopMNet と同じ結論)。
- **Glaux への示唆 [推測]**
  - 骨格の音は全体の約 1/3 で、強拍だけに限らず、長い音とシンコペーションも入れる。
  - 骨格の段で人(や LLM)が直せる窓口を作る。

### 1-2. MusicFrameworks: 階層の構造表現による制御可能な旋律生成 [一次・本文]

- 出典: Shuqi Dai, Zeyu Jin, Celso Gomes, Roger B. Dannenberg. "Controllable Deep Melody Generation via Hierarchical Music Structure Representation." ISMIR 2021。arXiv:2109.00663。https://arxiv.org/abs/2109.00663
- **要点**: 曲を「音楽の枠組み(music framework)」で表し、上から順に生成する。
  1. 区間と句の構造(AABBB のような反復。自動解析で取り出す)
  2. 句ごとの**基本旋律**: 2 拍ごとに最も多い音高を 2 分音符で並べたもの
  3. 句ごとの**基本リズム形**: 小節ごとに「リズムの型の名札(同じ名札 = 似たリズム)」と「複雑さ = 音数 / 16」
  4. 2 拍単位のリズムの型(256 通り)を生成
  5. 基本旋律・リズム・和音から実際の旋律を生成
- **反復の作り方**: 前の句の頭を写して続きを作るか、前の句と似た基本旋律から作る。似た句を作るときは、**DTW による輪郭の類似度が 0.7 以上**の基本旋律だけを受け入れる。100 案を作って確率の最も高いものを選ぶ。
- **位置の特徴**
  - 句の中の位置
  - その句が区間の終わりか
  - 小節の頭か
  - 小節の中の位置
- **制御の精度**: 生成した旋律を解析し直すと、基本旋律は目標と 92.27% 一致した。リズムの名札は 94.63%、複雑さ(±0.2 以内)は 81.79% 一致した。
  - 生成した旋律で句の終わりが主音になる確率は 48.28%、区間の終わりでは 87.63%。学習データはそれぞれ 49.01%、86.57%。
- **主観評価**: 196 人、1212 組。
  - 基本旋律と基本リズム形を挟むと、挟まない生成より有意に好まれた。
  - 生成した基本旋律から作った旋律と、人の曲の基本旋律から作った旋律は、ほぼ同じ評価だった。
  - 要旨: 生成した旋律は約半数で「POP909 の人の曲と同等以上」と評価された。
- **限界**: 長調・三和音のみ、ハ長調に移調。データは中国のポップス(POP909)。
- **Glaux への示唆 [推測]**: 「2 拍ごとの代表音」と「小節ごとのリズムの名札 + 複雑さ」は、学習なしでも作れる軽い中間表現で、LLM にも読み書きしやすい。

### 1-3. 最短経路による旋律の還元(AMRA)とその下流 [一次・本文 + 一次・コード]

- 出典: Ziyu Wang, Yuxuan Wu, Roger B. Dannenberg, Gus Xia. "Automatic Melody Reduction via Shortest Path Finding." ISMIR 2025。arXiv:2508.01571。https://arxiv.org/abs/2508.01571 、コード https://github.com/ZZWaang/melody-reduction-algo (Whole-song 生成(2-1)の「縮めたリードシート」もこれで作っている)
- **要点**: 句の音を頂点とし、すべての前向きの辺 xi→xj(i<j)を張る。**還元 = x1 から xN への最短経路**とみなす。辺を選ぶことは「その間の動きより xi→xj の動きが大事」という意味になる。
- **辺の種類と費用(論文の式)**(D = 2 小節以内)

  | 辺の種類 | 意味 | 費用 |
  |---|---|---|
  | 延長(PE) | 同じ音高(刺繍音などを飛ばせる) | 0.1 |
  | 線的(LE) | 2 度(半音か全音) | 0.3 |
  | 仮想の延長(IPE) | 同じ音名(オクターブ違い) | 1.0 |
  | 仮想の線的(ILE) | 複合 2 度 | 1.3 |
  | 分散(AE) | 同じ和音の中の 3 度以上 | 1.5 |
  | その他(UE) | 上以外 | 3.0 |

  - 距離の費用は (j−i)^1.6。これが大きいほど還元は少なくなる。
  - 行き先の音の重要度 α を掛ける。α は次の 4 つの積。
    - 音高: 音域の端ほど小さい
    - 拍: 強拍 0.85 / 拍 0.95 / 8 分 1.05 / 16 分 1.15
    - 長さ: 2 分以上 0.85 … 16 分 1.15
    - 和音: 和音の音 0.85 / 非和声音 1.15
  - 費用の合計 = α(xj) ×(距離の費用 + 種類の費用)。先取音(anticipation)は次の和音に属すとみなす。
  - 後処理
    - 選ばれた音を和音ごとの箱に入れ、決まったリズムの型に並べる(最細は 4 分音符。第 5 類対位法風)。
    - 同じ音の延長はまとめる。
    - 和音をまたぐ延長は掛留にする。
- **コードとの違い(移植するときの注意)[一次・コード]**: 公開コードの係数は論文と少し違う(和音の音 0.6 / 非和声音 1.4、長さ 0.9〜1.1)。どちらも「経験で決めた値で、データからの推定は今後」と書かれている。
- **評価**: 45 人(7 割以上が 2 年以上の音楽教育歴)。ポップス・民謡・クラシックの 8 小節を比べた。
  - 比較相手は「2 拍ごとの最多音(MusicFrameworks の方式)」と「VAE の潜在空間での間引き」。
  - 忠実さ・和声との整合・総合の音楽性で、**ほぼすべて有意に上回った**(ポップスの忠実さだけ p<0.075 の傾向)。
  - 下流の課題: 還元を条件に拡散モデルで変奏を作ると、「2 拍ごとの最多音」を条件にしたときより、独創性と音楽性で有意に好まれた。「2 拍ごとの最多音」の方は**音高の変化が平ら**になりやすかった。
- **Glaux への示唆 [推測]**: この還元を「生成した旋律を読み返す」ための分析器として使える。骨格の生成にも使え、費用を逆向きに使って「良い骨格の条件」にもなる(7 章)。

### 1-4. GTTM のタイムスパン木による旋律の操作(浜中・平田・東条)[一次・本文(ICMC 2009)+ 一次・公式ページ]

- 出典
  - Hamanaka, Hirata, Tojo. "Implementing 'A Generative Theory of Tonal Music'." Journal of New Music Research 35(4), 2006。doi:10.1080/09298210701563238 [書誌のみ確認]
  - "Melody Morphing Method based on GTTM." ICMC 2008 [ページの要旨]
  - "Melody Extrapolation in GTTM Approach." ICMC 2009 [本文]。https://gttm.jp/hamanaka/wp-content/uploads/2015/12/hamanaka_icmc2009.pdf
  - "Implementation of melodic morphing based on generative theory of tonal music." JNMR, 2022/2023。doi:10.1080/09298215.2023.2169713 [書誌のみ確認]
  - "Melody Slot Machine." ACM MM 2019 ほか [公式ページ]。https://gttm.jp/hamanaka/en/melody-slot-machine/
- **要点**
  - タイムスパン木は二分木で、大事な音ほど根に近い。木を途中の高さで切り、それより下の枝の音を落とすと、**段階的に抽象化した旋律**が得られる(D ⊒ E ⊒ F)。
  - 木の演算(平田による)
    - 包摂 ⊑(具体 ⊑ 抽象)
    - meet ⊓: 2 つの木の、上から見て共通する最大の部分
    - join ⊔: 構造が矛盾しない限り 2 つの木を合わせる
  - **旋律の分割還元**: 旋律 A と A⊓B の差分の枝から音を 1 つずつ落とし、中間の旋律 C1…Cn を作る。
  - **分割増強**(外挿): 差分の枝で最も長い音を選び、最も強い拍で 2 つに割る。強拍側は元の高さのまま、もう一方は Tonal Pitch Space で**最も安定な高さ**にする。これを L 回繰り返し、音を増やす。
  - **肉付けを規則で行う最小の手順の例**になっている [推測]。
  - 評価(ICMC 2009): 10 組の旋律で、外挿した旋律が類似度の条件を満たすことだけを確かめた。聴取実験は無い。
  - Melody Slot Machine(公式ページ): 区間ごとに複数の変奏を用意し、ダイヤルで切り替える。GTTM で構造を解析しているので、途中で別の変奏に切り替えても構造が崩れないという。
    - 音楽学者が変換法で作曲した実験では、**音の 78.5% が変換法で生成され、残り 21.5% を人が足して直した**。
- **自動解析の系譜**(ATTA → FATTA → σGTTM → deepGTTM-I〜IV(2025))[二次: 公式ページの一覧と書誌]: 当初は規則の重みを人が調整する半自動だった。後に統計や深層学習で自動化した。
- **関連**: Nakamura, Hamanaka, Hirata, Yoshii. "Tree-structured probabilistic model of monophonic written music based on GTTM." ICASSP 2016。doi:10.1109/ICASSP.2016.7471680 [書誌のみ。本文は未確認]。タイムスパン木を確率文法として扱う生成モデルとみられる [推測]。
- **限界**
  - 入力は楽譜(MusicXML)で、GTTM の規則の多くは重みの調整が要る。
  - 対象はおもに古典的な調性音楽。
  - AMRA の論文も「自動解析と人の解釈にはまだ差があり、コードも公開されていないものが多い」と書いている。

### 1-5. ProGress: Schenker の背景の型に合わせて句をつなぐ [一次・本文]

- 出典: Stephen Ni-Hahn, Chao Péter Yang, Mingchen Ma, Cynthia Rudin, Simon Mak, Yue Jiang. "ProGress: Structured Music Generation via Graph Diffusion and Hierarchical Music Analysis." NeurIPS 2025 Creative AI Track。arXiv:2510.10249。https://arxiv.org/abs/2510.10249
- **要点**
  1. リズムの枠(データから選んだ句のリズム)に、グラフ拡散で音度を割り当てた句をたくさん作る。
  2. 規則で不合格の句を捨てる(不適切な音程や対位法の動き、和声進行として解釈できない句)。
  3. 残った句を、**文献から集めた Schenker の背景の型**に合わせてつなぐ。
     - 例: 3 線の Ursatz で I−V−I、上声は 3̂−2̂−1̂。
     - 句 1 は主調で完全終止し、上声は 3̂。
     - 句 2 は属調で終止し、上声は全体で 2̂(局所では 5̂)。
     - 句 3 は主調で完全終止し、上声は 1̂。
  4. 句の間は転回和音(pivot chord)で転調してつなぐ。
- **音域の扱い**: 声部ごとに「中心の高さ」を決める。2 度で進めるときは順次で進み、大きな跳躍になるときは中心に近い音を選ぶ。**素朴に一番近い音を選ぶと、旋律が極端に高くまたは低くなる**ため。
- **評価**: 45 人(専門家 13 人)。Bach のコラール様式で、DeepBach、NotaGen、Music Transformer、TonicNet、Bach 本人と比べた。
  - 「変・悪い所があった」の割合が最も低かった。
  - 好みの対比較でも他の手法を上回り、NotaGen とはほぼ互角。パラメータは 300 万で、NotaGen の 5.16 億と比べて大幅に小さい。
  - 「楽しさ」は Bach より有意に高かった。著者は「Bach ほど和声的に冒険しないから」と解釈している。
- **限界**: 対象は Bach のコラール(4 声)。ポップスの旋律への適用は示されていない。
- **Glaux への示唆 [推測]**: 「区間の背景 = 句の終わりの音度の並び(例: 3̂ → 2̂ → 1̂)」を先に決めてから句を作るのは、学習なしでもできる。

## 2. 曲全体を階層で作る研究

### 2-1. Whole-song hierarchical generation(Wang, Min, Xia, ICLR 2024)[一次・本文]

- 出典: Ziyu Wang, Lejun Min, Gus Xia. "Whole-Song Hierarchical Generation of Symbolic Music Using Cascaded Diffusion Models." ICLR 2024。arXiv:2405.09901。https://arxiv.org/abs/2405.09901 、https://github.com/ZZWaang/whole-song-gen
- **要点**: 4 層の「階層の音楽言語」を、上から順に拡散モデルで生成する。

  | 層 | 中身 | 時間の細かさ | 1 回に見る範囲 | 構造の焦点 |
  |---|---|---|---|---|
  | 形式 | 調の変化と句(種類 + 残り小節数) | 小節 | 最大 256 小節 | 曲の形式 |
  | 縮めたリードシート | 旋律の還元(1-3 の最短経路)+ 簡略化した和音 | 拍 | 32 小節 | 句の類似・展開・**終止** |
  | リードシート | 旋律 + 和音 | 16 分 | 8 小節 | 旋律のパターン・類似・つながり |
  | 伴奏 | ピアノ伴奏 | 16 分 | 8 小節 | 伴奏の型・旋律との関係 |

  - 句は 6 種類(A = ヴァース、B = サビ、X = その他の旋律、i = イントロ、o = アウトロ、b = ブリッジ)。句の中の値は「1 − 句の中の位置 / 句の長さ」の**残り数**で表す。句の中のどこにいるかが下の層に伝わる。
  - 下の層は 3 種類の条件で作る。
    - 背景条件: 上の層を同じ時間位置で重ねる。
    - 自己回帰条件: 句の種類が似た過去の区間を最大 2〜3 個参照する。
    - 外部条件: 事前学習した和音・リズム・伴奏の潜在表現。
  - 生成は、前半を固定して後半を塗り直す(inpainting)ことを半分ずつずらしながら繰り返す。
- **生成例の観察(本文 4 章)**
  - 3 つのヴァースは、**シンコペーションが多く音域が狭い**。
  - 2 つのサビは、**歌うようで音域が広い**。
  - 句の境界では主和音か属和音で終止する。
  - 後半は音高が高く動きも多く、曲の終わり前に山が来る。
- **評価**
  - 客観指標 ILS(同じ種類の句どうしの類似 ÷ 全句の平均類似。高いほど構造が明確)は次のとおり。

    | 対象 | 旋律の輪郭 | リズム | 和音 | 伴奏 |
    |---|---|---|---|---|
    | 本手法 | 2.05 | 1.49 | 1.32 | 1.19 |
    | 句の名札つき Transformer-XL | 1.89 | 1.71 | 0.68 | 0.74 |
    | 人 | 2.28 | 2.30 | 1.42 | 1.68 |

  - 主観評価は 57 人。32 小節の全曲では「境界の明確さ」「句の類似」で基準を有意に上回った。8 小節の断片でも、自然さと音楽性で上回った(数値は図のみ)。
- **限界(著者)**
  - 最大 256 小節。拍子の変更は扱えず、3 拍子は弱い。
  - **終わりが主和音に解決しないことがある。**
  - 空の小節など明らかな失敗が時々出る。
- **Glaux への示唆 [推測]**: 「句の残り小節数」と「句の種類」を各音の生成に渡すだけで、句の中の位置による振る舞いの違い(終わりほど長い音・安定した音)を作りやすくなる。

### 2-2. Compose & Embellish(Wu & Yang, ICASSP 2023)[一次・本文]

- 出典: Shih-Lun Wu, Yi-Hsuan Yang. "Compose & Embellish: Well-Structured Piano Performance Generation via A Two-Stage Approach." ICASSP 2023。arXiv:2209.08212。https://arxiv.org/abs/2209.08212
- **要点**: 先にリードシート(旋律 + 和音 + 句の記号)を作り(Compose)、次にそれを条件に伴奏と表情を付けたピアノ演奏を作る(Embellish)。
  - 句の記号: 句の頭の小節に `[PHRASE A〜H]` と `[REP_START n]`、終わりに `[REP_END]` を置く。句の構造は編集距離と A* 探索で解析する(Dai ら 2020 の方法)。
  - 1 段目はリードシートだけなので、多トラック曲(Lakh MIDI の 1.5 万曲)で事前学習できる。
- **評価**: 15 人、3〜5 分の全曲。

  | 手法 | 一貫性 | 正しさ | 構造 | 豊かさ | 総合 |
  |---|---|---|---|---|---|
  | CP Transformer | 2.38 | 2.49 | 2.33 | 2.64 | 2.33 |
  | **C&E** | 3.53 | 3.11 | 3.36 | 3.29 | 3.18 |
  | 人 | 4.42 | 4.13 | 4.44 | 4.24 | 4.40 |

  - 客観の構造性(fitness scape の SI)は、CP Transformer と実データの差を中・長期でほぼ半分に縮めた。
- **限界**
  - **2 段目で構造性が落ちる**。リードシートの段では SI_long 36.6(実データと同じ)だったのが、演奏にすると 25.8。旋律はほぼ 100% 写しているのに、伴奏と表現に由来する反復が作れない。
  - 事前学習しないと「同じ小節を 6 回以上続けて繰り返す」過剰反復が増えた(5.5%。事前学習ありは 2.5%、実データは 0.5%)。
- **Glaux への示唆 [推測]**: 上の段で良い構造を作っても、下の段が上の段の反復を写さなければ耳には届かない。肉付けの段にも「前の同じ種類の句の肉付けを参照する」経路が要る。

### 2-3. MeloForm: 専門家システム(規則)で形式を作り、ニューラルで磨く [一次・本文]

- 出典: Peiling Lu, Xu Tan, Botao Yu, Tao Qin, Sheng Zhao, Tie-Yan Liu. "MeloForm: Generating Melody with Musical Form based on Expert Systems and Neural Networks." ISMIR 2022。arXiv:2208.14345。https://arxiv.org/abs/2208.14345
- **要点(Glaux の今の方式に最も近い)**
  - 規則の段(専門家システム)
    - 和音進行とリズムの型から 1〜2 小節の**動機**を作る。和音の音から始め、装飾音を足し、隣の音との音程は 7 半音以内。
    - 反復進行(sequence)・変形・終止で**動機を句に展開**する。
    - 句を反復・変奏して区間にし、区間を並べて曲にする(例: A(a1, a1)B(b1, b2))。
    - 区間の対比は、リズムの密度・音の長さ・音高の範囲(高いほど緊張)で作る。
  - ニューラルの段: Transformer が、**似た句をまとめて 1 反復ずつ**書き直す。
    - リズム・和音・終止の記号は条件として固定し、主に音高を直す。
    - 句の頭に `AVGPITCH`(平均音高)と `SPAN`(最高と最低の差)の指示を入れ、区間の違いを保つ。
- **評価**: 10 人、30 曲。

  | 手法 | 構造 | 主題 | 豊かさ | 総合 |
  |---|---|---|---|---|
  | Music Transformer | 3.00 | 3.21 | 2.11 | 2.32 |
  | MELONS | 3.18 | 3.07 | 2.64 | 2.89 |
  | 句の名札つき言語モデル | 2.61 | 2.93 | 2.96 | 2.96 |
  | **MeloForm** | 3.68 | 3.57 | 3.43 | 3.61 |
  | POP909(人) | 4.06 | 3.83 | 4.00 | 4.11 |

  - 形式の制御精度は 97.79%。平均音高の制御は 92.5%、音域幅の制御は 99.71%。
  - 削った場合との比較(好みの対比較)では、次のどれもが好まれなかった。
    - 規則の展開をやめてランダムに並べる
    - 規則の段を無くす
    - **ニューラルの段を無くす(規則だけ)**
    - リズムの条件を粗くする
    - 反復の句をそのまま写す
    - 平均音高と音域幅の指示を外す
- **限界**
  - 規則だけの旋律は「形式は正確だが豊かさに欠ける」と著者自身が書いている。これが 2 段目を入れた動機。
  - 句の名札だけで反復を作った言語モデル(制御精度 100%)は評価が低かった。**単に句を繰り返すだけでは不十分**。
- **Glaux への示唆 [推測]**
  - 試した人の評価(「欠点は無いが特徴が無い」)は、MeloForm の「規則だけでは豊かさに欠ける」と同じ症状に見える。
  - 学習モデルを持たない Glaux では、2 段目の代わりに「上の層の計画に沿った探索による書き直し」と「LLM による句単位の書き直し」を使うのが現実的。
  - 句ごとの平均音高と音域幅を**計画の変数として明示**するのは、MeloForm で精度よく効いたので採用しやすい。

### 2-4. MELONS / PopMNet: 小節どうしの関係のグラフ [一次・本文(MELONS)/ 二次(PopMNet)]

- 出典: Yi Zou, Pei Zou, Yi Zhao, Kaixiang Zhang, Ran Zhang, Xiaorui Wang. "MELONS: Generating Melody with Long-Term Structure Using Transformers and Structure Graph." ICASSP 2022。arXiv:2110.05020。https://arxiv.org/abs/2110.05020
- **中間表現**: 小節を頂点とし、前の小節との関係を種類つきの辺にする。関係は 8 種で、優先度の順に次のとおり。

  | 関係 | 定義 | POP909 での割合 |
  |---|---|---|
  | 反復 | 同じ小節 | 44% |
  | 移高 | 調の中で高さをずらしたもの | 1% |
  | 音高の進行 | 同じリズムで、音高列の一致 50% 以上 | 3% |
  | リズムの反復進行 | 同じリズムで、音高列の一致 50% 未満 | 6% |
  | 旋律の進行 | 同じ高さとリズムの 3 音以上を共有 | 11% |
  | 周回の進行 | 小節内で 3 回以上鳴る音が 5 半音以上上下する | 5% |
  | 和声的な終止 | 音の密度の曲線の極小に主和音の音がある | 6% |
  | 休み | 音が無い小節 | 6% |

  - 各小節は、近い小節から遠い小節へ順に照合し、最も優先度の高い関係を 1 本だけ持つ。4 つのデータの間で関係の分布の相関は 0.98 を超えた。
- **生成**
  1. 最初の 8 小節(動機)を与え、関係の列 (i, j, 種類) を自己回帰で生成する。
  2. 反復はそのまま写す。
  3. 他の関係は、直前 8 小節と参照小節と関係の種類を条件に小節を生成する。
- **評価**: 専門家 12 人、80 曲。
  - 総合の MOS は MELONS 3.20、実曲の構造を与えた MELONS-R 3.22、PopMNet 2.17、CP Transformer 2.13、人 4.39。
  - 構造の項目は 3.53、人は 4.54。
  - 関係の正しさ: リズムの反復進行 92.88%、移高 77.33%。
- **限界**: 生成したグラフと実曲のグラフの差は有意でなく、**差は旋律生成の側**にある(著者)。関係はすべて小節単位で、句や区間の階層は明示しない。
- **Glaux への示唆 [推測]**: 8 種の関係は、Glaux の `motif::Op`(Seq, Frag, Vary …)と対応づけやすい。**「どの小節がどの小節を何の関係で参照するか」の地図を先に作る**のは規則でできる。

### 2-5. TeleMelody(テンプレートを介した歌詞 → 旋律)と SongMASS [一次・本文]

- 出典
  - Zeqian Ju, Peiling Lu, Xu Tan ほか. "TeleMelody: Lyric-to-Melody Generation with a Template-Based Two-Stage Method." EMNLP 2022。arXiv:2109.09617。https://arxiv.org/abs/2109.09617
  - Zhonghao Sheng ほか. "SongMASS: Automatic Song Writing with Pre-training and Alignment Constraint." AAAI 2021。arXiv:2012.05168
- **TeleMelody の中間表現(テンプレート)**
  - 調: 曲の頭に 1 語
  - 音ごとの 3 語: 和音・リズムの型(小節内の拍位置 0〜3)・**終止**(無し / 半終止 / 完全終止)
  - 終止の取り出し規則
    - 1 拍未満の短い音、または次の音との間隔が 1.5 拍未満の音は「無し」。
    - 主和音の根音(または推定和音が主和音)の音は「完全終止」。主和音の他の音で、間隔が 2 拍を超える音も、確率 0.3 で完全終止にする。
    - それ以外は「半終止」。
  - 歌詞からは、読点を半終止、句点を完全終止に対応させる。
  - テンプレート → 旋律のモデルは、旋律から取り出したテンプレートで自己教師学習する。注意の位置を「テンプレートの対応する語」に寄せる正則化も入れる。
- **評価**: 10 人(アマチュア 7、専門家 3)。
  - 英語の総合: TeleMelody 3.3、SongMASS 2.2、Transformer 1.8。
  - 中国語の総合: 3.2 / 1.7 / 1.5。
  - 構造(反復と印象的な区間があるか): 英語 3.3 / 2.3 / 1.8。
- **限界(著者)**: 人の作品より多様性が低い。
- **SongMASS**: 歌詞と旋律の分離事前学習と、文単位の注意の制約、動的計画法による音節と音の対応づけ。**階層の計画は持たない**端から端までのモデルで、TeleMelody の比較相手として上の数値に出ている。
- **Glaux への示唆 [推測]**: 「句の区切り = 終止の種類」を先に決め、終止の音に長さと安定した音度を割り当てるのは、規則だけでできる。

### 2-6. 階層デコーダ: MusicVAE と CM-HRNN [一次・本文]

- **MusicVAE**: Adam Roberts, Jesse Engel, Colin Raffel, Curtis Hawthorne, Douglas Eck. "A Hierarchical Latent Vector Model for Learning Long-Term Structure in Music." ICML 2018。arXiv:1803.05428
  - 潜在ベクトルから「指揮者(conductor)」RNN が小節ごとの埋め込みを作り、下の RNN が各小節を生成する。
  - 16 小節の旋律・トリオ・ドラムで、階層版は平坦版より「音楽的」と有意に多く選ばれた(p<0.01/3)。実データとは有意差が無かった。192 評価ずつ。
  - 著者はドラムについて、「実データより多く選ばれたのは(有意でない)、聞き手が**変化を好む偏り**のため。実データの方が反復的」と注記している。
- **CM-HRNN**: Guo Zixun, Dimos Makris, Dorien Herremans. arXiv:2102.09794(2021)
  - 小節・拍・音の階層 RNN で、和音を条件にする。
  - AttentionRNN より反復が多く(圧縮率が高く)、調性の緊張が低い。41 人の聴取で長期構造と総合が上回った。
- **限界**: どちらも学習モデル。階層は「時間の粗さ」だけで、音楽の役割(骨格・終止)は明示しない。

### 2-7. 注意の構造の工夫: Museformer・構造を入れた位置符号・PopMAG・SymphonyNet

- **Museformer** [一次・本文]: Botao Yu ほか. NeurIPS 2022。arXiv:2210.10349
  - 学習データで小節どうしの類似度を間隔ごとに平均すると、**1・2 小節前と、4 の倍数の小節前が特に似ている**。この周期はジャンルを問わなかったという。
  - これに基づき、1, 2, 4, 8, 12, 16, 24, 32 小節前は全部の音に注意を向け、その他の小節は要約の語にだけ向ける。
  - 10 人(音楽経験者 7 人)の 10 段階評価: 長期構造 6.72(Music Transformer 5.30)、総合 7.12(5.90)。
  - 限界: ランダムに出力するので、構造がいつも期待どおりにはならない。音楽性は人に遠い。
  - **Glaux への示唆 [推測]**: 「1, 2, 4, 8 小節前の対応する小節を参照して作る」は規則でも実装できる反復の既定値になる。
- **Structure-informed positional encoding** [一次・要旨]: Agarwal, Wang, Richard. ICASSP 2024。arXiv:2402.13301。多段の構造(区間・句など)の情報を位置符号に入れると、旋律と構造の一貫性が上がった。
- **PopMAG** [一次・要旨]: Ren ほか. ACM MM 2020。arXiv:2008.07703
  - 多トラックを 1 列に並べる MuMIDI 表現と、長い文脈の記憶。伴奏生成が対象で、旋律の計画は持たない。
  - 人の曲と比べた勝率は 38〜42%。
- **SymphonyNet** [一次・要旨]: Liu ほか. ISMIR 2022。arXiv:2205.05448。交響曲の多トラック生成(並び替え不変の表現・Music BPE)。**旋律の階層の計画は扱わない**ので、本テーマへの寄与は小さい。

### 2-8. 主題の条件づけと穴埋め事前学習 [一次・要旨/本文の一部]

- **Theme Transformer**(Shih ら, IEEE TMM 2022。arXiv:2111.04093): 冒頭の数小節を与えて続きを書かせるだけだと、旋律はだんだん主題から離れていく(図 1)。主題を「何度も現れるべき素材」として別経路で参照させると、反復ともっともらしい変奏が増えた。
- **MelodyGLM**(Wu ら 2023。arXiv:2309.10738): 音高とリズムの n-gram と長い区間の穴埋めを事前学習の課題にした。続きの生成で構造 +0.78、総合 +0.94。穴埋めでは人の作品に近い評価だった。
- **Music SketchNet**(Chen ら, ISMIR 2020。arXiv:2008.01291): 音高の輪郭とリズムを分けた潜在表現で、欠けた小節を前後の文脈とユーザーの指定から埋める。**局所の書き直しを前後に合わせる**研究として、改稿のループに関係する。

## 3. 旋律の構造の表現(理論とその計算実装)

### 3-1. Schenker の還元(背景・中景・前景)[二次(各論文の説明)+ 一次・本文(ProGress・AutoSchA)]

- 理論の要点(ProGress・Whole-song・WuYun の説明による)
  - 曲は背景(根本構造 = Ursatz。上声の下行 Urlinie 3̂−2̂−1̂ など + 低音の I−V−I)から、中景(形式と大まかな展開)を経て、前景(実際の音)へと再帰的に「延長(prolongation)」される。
  - 延長の基本の型は 3 つ。
    - 同じ音を保つ
    - 順次の線(linear progression)
    - 分散和音(arpeggiation)
  - AMRA(1-3)の辺の種類は、この 3 つに対応している。
- **計算実装**
  - Kirlin & Jensen(41 曲の分析コーパスに基づく確率的な方法。2011〜2015)と Marsden(2010)[二次: AutoSchA の関連研究より]
  - AutoSchA(Ni-Hahn ら 2025。arXiv:2512.18232)[一次・要旨]: グラフニューラルネットで階層の分析をする。Baroque のフーガ主題で人の専門家と同程度だったという。
  - 分析の新しいデータセットと表記(arXiv:2408.07184)[書誌のみ]
- **生成への利用**
  - ProGress(1-5): 背景の型に合わせて句をつなぐ。
  - Whole-song(2-1)と AMRA(1-3): 縮めた旋律を中間の層にする。
- **限界**: 分析は 1 句 30 分以上かかり、正解が一つに決まらない(主観的)。多くは西洋古典の調性音楽が前提。

### 3-2. GTTM(Lerdahl & Jackendoff 1983)[二次 + 一次・本文(浜中 ICMC 2009)]

- 4 つの構造がある。
  - 分節構造(grouping): 句の切れ目。休符・長い音の後や、変化の大きい所で切れる。
  - 拍節構造(metrical): 拍の強さの階層。
  - **タイムスパン還元**: 分節と拍節から、各区間で最も重要な音を選んで木にする。リズム面の骨格。
  - **延長還元**: 緊張と弛緩の木。和声面の骨格。WuYun は「延長還元では重要な事象ほど緊張が低い」を調の骨格の根拠にしている。
- 計算実装: 浜中らの ATTA/FATTA/σGTTM/deepGTTM(1-4)。延長還元の緊張は Lerdahl の Tonal Pitch Space の緊張モデルにつながる(4-1)。
- Foscarin ら "Predicting Music Hierarchies with a Graph-Based Neural Decoder"(arXiv:2306.16955, 2023)[書誌のみ]: 階層(木)を予測する神経モデル。
- **限界**: 規則の間の衝突を解く重みを人が決める必要があった(浜中らが「exGTTM」で再定式化した理由)。楽譜が前提。

### 3-3. 骨格音の抽出法の比較(まとめ)

| 方法 | 入力 | 選ぶ基準 | 結果の割合・細かさ | 学習 | 出典の確かさ |
|---|---|---|---|---|---|
| WuYun リズムの骨格 | 旋律 | 強拍・強拍の長い音・シンコペーションの長い音 | 約 34% | 不要 | 一次・本文 |
| WuYun 調の骨格 | 旋律 + 調 | リズムの細胞の中で螺旋配列の緊張が最小の音 | 約 43% | 不要 | 一次・本文 |
| MusicFrameworks 基本旋律 | 旋律 | 2 拍ごとの最多音 | 2 分音符の列 | 不要 | 一次・本文 |
| AMRA 最短経路 | 旋律 + 和音 | 辺の種類(同音・2 度・分散)と距離と音の重要度 | 最細 4 分音符 | 不要 | 一次・本文 + コード |
| GTTM タイムスパン木 | 楽譜 | 分節・拍節の規則と平行性 | 木の任意の高さ | 半自動〜深層 | 一次・本文(ICMC)+ 二次 |

## 4. 計画の表現と条件づけ(音域の軌跡・密度・緊張・句構造)

### 4-1. 緊張のモデル

- **Lerdahl & Krumhansl 2007 "Modeling Tonal Tension"**(Music Perception 24(4)。doi:10.1525/mp.2007.24.4.329)[一次・要旨]
  - 延長構造・音高空間・表面の緊張・引力の 4 要素で、緊張の上がり下がりを予測する。
  - 聴き手が記録した緊張と比べ、理論の範囲内で別の分析の可能性も示した。
- **Farbood 2012 "A Parametric, Temporal Model of Musical Tension"**(Music Perception 29(4)。doi:10.1525/mp.2012.29.4.387)[一次・要旨]
  - 和声・**音高の高さ**・旋律の期待・強さ・**発音の頻度(密度)**・テンポ・拍節・リズムの規則性・シンコペーションの寄与を実験で調べた。
  - 線形・非線形の単純な組み合わせでは連続の緊張の評定を説明できなかった。
  - 「動く知覚の窓」と「傾向の目立ち(trend salience)」に基づくモデルで高い相関を得た。
  - **緊張は各時点の値の和ではなく、変化の向きと持続で感じられる**という点が計画の設計に効く [推測]。
- **Herremans & Chew の螺旋配列の緊張(tension ribbons, 2016)**(MorpheuS 本文の説明より)[一次・本文]
  - 音の雲の直径(不協和の広がり)
  - 雲の運動量(隣の雲との距離)
  - 引張(雲の重心と調の距離)
- **MorpheuS**(Herremans & Chew, IEEE Trans. Affective Computing 2017/2019。arXiv:1812.04832)[一次・本文]
  - 型の曲のリズムを固定する。
  - 反復パターン(COSIATEC / SIATECCompress で検出)を**硬い制約**にする。最初の出現の音高だけを変数にし、他の出現は平行移動で決まる。
  - 目標の緊張曲線とのユークリッド距離を最小にするように、可変近傍探索(VNS)で音高を割り当てる。近傍は 1 音の変更・2 音の入れ替え・縦の組の変更。改善すれば即採用(first descent)で、変更の後は 4 時間枠だけ戻って探索する。
  - **専門家の指摘**
    - 素材の反復はできるが**展開しない**。
    - 反復区間の戻り目で和声がぎこちなく、**つなぎが下手**。
    - **終止の型が変な場所に入る**。
    - **緊張の水準が句の構造と関係していない**ので、句に沿った和声の展開ができていない。
  - 一方で「恐れを知らず冒険する」と面白がる評もあった。
- **Guo, Simpson, Magnusson, Kiefer, Herremans 2020**(arXiv:2010.06230)[一次・要旨]: 引張と雲の直径を VAE の潜在空間の方向として学び、緊張の向きと水準を制御した。リズムは種の断片に似たまま音高が変わる。主観評価は無い。
- **WuYun**: 螺旋配列の引張で「最も緊張の低い音」を骨格に選ぶ(1-1)。
- **限界(まとめ)**: 緊張の曲線だけを目的にすると、句や終止の構造と無関係に音が決まる(MorpheuS)。**緊張は句構造の下位の変数として、句の中の位置(頭・中・終止)と結びつけて計画する必要がある** [推測]。

### 4-2. 音域と密度の計画

| 研究 | 計画の変数 | 単位 | 効果・精度 | 確かさ |
|---|---|---|---|---|
| MeloForm | 平均音高 `AVGPITCH`・音域幅 `SPAN`・リズムの密度 | 句 | 92.5% / 99.71% で制御。外すと好まれない | 一次・本文 |
| FIGARO | 拍子・和音・楽器・**音の密度・平均音高**・平均の強さ・平均の長さ(量子化) | 小節 | 人の曲との勝率 39.3%(次点 33.2%)。691 人・7569 比較 | 一次・本文 |
| MusicFrameworks | リズムの型の名札・**複雑さ(音数/16)**・基本旋律 | 小節 / 2 拍 | 複雑さの一致 81.79%(±0.2)、輪郭の一致 92.27% | 一次・本文 |
| Whole-song | 句の種類・**残り小節数**・調 | 小節 | ILS が基準より高い | 一次・本文 |
| MuseCoco | 音域・リズムの強さ(平均の密度)など | 曲全体 | 属性の制御精度はほぼ 100% | 一次・本文の一部 |
| MusicVAE | 密度などの属性ベクトル | 2〜16 小節 | 属性の加減で意図した変化 | 一次・本文 |

- FIGARO: von Rütte, Biggio, Kilcher, Hofmann. ICLR 2023。arXiv:2201.10936。**人が読める粗い記述(小節ごとの特徴)は、記述に無い性質(クロマやグルーヴの類似)まで導く強い帰納的偏りになる**、と著者は書いている。
- Whole-song の生成例(2-1): **ヴァースは音域が狭くシンコペーション、サビは音域が広く歌うよう、後半は高く動きも多い**。計画の型の実例になる [一次・本文]。
- 音域の弧・最高音は一度だけ・句はアーチか下行といった認知研究の知見は、別レポート(cognition.md)で扱っている。

### 4-3. 句・区間・終止の計画(コーパスの事実)

- **Dai, Zhang, Dannenberg 2020**(Joint Conf. AI Music Creativity。arXiv:2010.07518)[一次・本文](POP909)
  - 旋律の句は 4 小節か 8 小節が大半。曲の大半は 2〜3 区間、1 区間に 1〜6 句、区別できる旋律の句は 2〜3 種類。
  - 反復する句が曲の 50〜90% を占める。
  - 和音
    - 句の頭と区間の終わりは I が多い。
    - 句の終わりは I と V がほぼ同数。**区間の途中の句は V、区間の終わりは I で終わりやすい**。
    - 区間の終わりの 58% が V−I。V→I の遷移確率は句の終わりで 0.89、区間の途中の句の終わりで 0.84、区間の終わりで 0.94。他の位置では 0.47。
  - 旋律の音度(I の和音の上)
    - 1̂ は区間の終わりに多く、句の頭や途中には少ない。
    - 3̂ は句の頭に多く、区間の終わりには少ない。
  - 音の長さ
    - 句の頭と途中は短い音が主。**句の終わりは長い音**。
    - 全音符以上の音の 72% は区間の最後の句の終わりにあり、区間の途中の句の終わりには 6.4% しか無い。
  - 年代とともに、句の間の類似は下がり(区間の対比が増え)、句の複雑さは上がった。
- **Dai, Yu, Dannenberg 2022 "What is missing in deep music generation?"**(ISMIR 2022。arXiv:2209.00182)[一次・本文]
  - 曲ごとの語彙: 曲の中のリズムと音高の型の種類は、データ全体から予想されるより少ない。曲の中の短い文脈の方が、大量の他曲より予測に効く。Music Transformer の出力は**リズムの型の種類が実曲より多く**、一度しか出ない型が多い(「間違いに聞こえる外れ値」)。
  - 反復の時間配置
    - 句の 50% 以上はすぐに繰り返される。ほぼすべての句が曲の 1/4 以内に繰り返される。
    - 79% の曲で、新しい素材は曲の長さの 15〜35%。
    - 曲の約 1/4 で新しい素材が入る。後半はほぼ反復か変奏。終わり近くにまた新しい素材が出る。
    - 予測の交差エントロピーもこの形に沿う。
  - 位置による違い
    - 実曲では、句の頭・中・終わりで音度の分布のエントロピーが有意に違う。主音の確率は句の終わりで 35%、他の位置で約 20%。
    - VAE の出力では、どの位置も 20〜21% で差が無い。
    - 著者:「句を作って型に貼り付ければ反復は作れるが、句の構造と他の要素が絡み合っているので、それだけでは実曲の性質を再現できない」。
- **Naruse ら 2022**(REMI に句と「小節の残り数」を足す)[二次: Whole-song と総説での紹介]

## 6. 横断的な教訓と限界

1. **上位の計画は機械で十分、差は肉付けにある**(WuYun・MELONS・MusicFrameworks の「生成した上位 ≈ 実曲の上位」)。Glaux では、計画を作る部分より**肉付けの語彙と、それを計画に沿わせる探索**に手間をかけるべき [推測]。
2. **硬い骨格は逆効果**: 強拍だけ、または音名が 1〜3 に偏った骨格は、ランダムの骨格より悪い(WuYun)。骨格にも揺らぎ(シンコペーション・長い音・音度の多様さ)が要る。
3. **骨格の量は約 1/3**: 少なすぎると導けず、多すぎると骨格そのものが旋律になり、肉付けの余地が無い(WuYun)。AMRA の還元(最細 4 分音符)も近い細かさ [推測]。
4. **規則だけでは「正しいが豊かでない」**(MeloForm の自己評価、MorpheuS の「展開しない」)。規則の段の後に、別の原理の段(学習・探索・人・LLM)を挟んだ系が評価を伸ばしている。
5. **下の段は上の段の反復を写さないと構造が耳に届かない**(Compose & Embellish で SI_long が 36.6 → 25.8)。
6. **緊張の曲線だけを合わせると句の構造を壊す**(MorpheuS)。終止の位置と種類は、緊張より先に句の構造から決める。
7. **位置による分布の違いが無いことが AI らしさ**(Dai 2022 の主音 20〜21% で平ら、Theme Transformer の漂流)。
8. **客観指標は当てにならない**。WuYun と PopMNet は、分布の重なりが良くても構造と音楽性が良いとは限らないと報告している。主観評価の人数も 10〜60 人と小さい。
9. **対象の偏り**: 多くが POP909(中国のポップス)・Wikifonia・Bach・4/4・長調。EDM のリードやループものへの一般化は未確認。

## 7. Glaux の上から下への旋律生成に取り入れられそうな中間表現と手順(学習モデル無し、規則と探索が中心)

以下はすべて [推測](上の一次情報からの設計案)。括弧内は根拠。

### 7-1. 中間表現(層)

- **L0 区間の計画 `SectionPlan`**(1 区間 = 8〜32 小節)
  - 句の分割と長さ: 4 / 8 小節が既定。区間の最後の句だけ伸ばす・縮める選択肢を持つ(Dai 2020、Whole-song の句の種類 + 残り小節数)。
  - 句ごとの終止: 無し / 半終止(V、2̂・5̂・7̂)/ 完全終止(I、1̂)。**区間の途中の句は半終止寄り、区間の最後は完全終止**(Dai 2020、TeleMelody)。
  - 小節ごとの**音域の中心と幅**の曲線(MeloForm の AVGPITCH / SPAN、Whole-song の「ヴァースは狭く、サビは広く、後半は高く」)。
    - 役割ごとの固定の `range` をやめ、区間の中の軌跡にする。
    - 区間で**最高音は 1 回**とし、その位置(例: 区間の 60〜80%)を計画に持つ(認知レポートの知見)。
  - 小節ごとの**密度**(音数/16。MusicFrameworks の複雑さ、FIGARO の密度)の曲線。句の終わりで下げ、終止の音は長くする(Dai 2020)。
  - 反復の地図: 小節 i が小節 j を、どの関係(反復 / 移高 / 音高の進行 / リズムの反復進行 / 旋律の進行 / 終止 / 休み)で参照するか。
    - MELONS の 8 種を `motif::Op` に対応させる。
    - 既定の参照先は 1・2・4・8 小節前(Museformer)。
    - 新しい素材は区間の 15〜35%(Dai 2022)。
  - 背景の線: 句の終わりの音度の並び。例: 3̂ →(半終止)2̂ →(完全終止)1̂、またはサビで 5̂ → … → 1̂(ProGress の Ursatz の型)。
- **L1 句の骨格 `Skeleton`**: おおむね 2 拍に 1 音(全体の約 1/3。WuYun の割合、MusicFrameworks の 2 分音符)。
  - 各音は位置・音度・高さ・「強拍 / 長い音 / シンコペーション」の種類を持つ。**強拍だけに固定しない**(WuYun)。
- **L2 リズムの骨格 `RhythmPlan`**: 小節ごとのリズムの型の名札(同じ名札 = 似たリズム)と複雑さ(MusicFrameworks)。曲の中で使うリズムの型の数を絞る(Dai 2022 の「曲ごとの小さな語彙」)。
- **L3 表面 `Notes`**: 骨格の音の間を、延長の型で埋めた結果。

### 7-2. 手順(上から下へ)

1. **L0 を作る**: 役割(verse / pre / chorus …)ごとの型から標本をとり、LLM や人が数値で直せるようにする。
2. **L1 骨格を探索で作る**: 骨格の候補の列を動的計画法かビームで探す。費用は AMRA の辺の費用を**生成向けに流用**する。
   - 同音の保持と 2 度の線を安く、同じ和音の分散を中くらい、それ以外を高くする。
   - L0 の音域曲線からの外れ、終止の音度の不一致、最高音の回数を罰する。
   - 強拍か長い音の位置では和音の音を選ぶ(AMRA の重要度、WuYun の調の骨格)。
   - 中心の高さへの引き戻しを入れ、極端な高低を防ぐ(ProGress)。
3. **L2 リズムを割り当てる**: 密度曲線と反復の地図に従い、動機のリズムの型を「関係」で写すか変える。
4. **L3 肉付け**: 骨格の隣り合う 2 音の間を、延長の型で埋める。
   - 型: 経過音・刺繍音・分散・先取・掛留・同音の反復・浜中の分割増強(最長の音を最強の拍で割り、安定な高さを割り当てる)。
   - **動機は「骨格の音程に掛ける装飾の型(diminution)」として扱う。** こうすると、動機の同一性を保ったまま、全体の波(骨格)に沿って形が変わる。今の方式は動機の中に弧を持たせて並べるので、全体の輪郭が変わらない。これが試した人の指摘する「局所の微調整が全体から浮く」原因とみられる。
5. **反復は下の段でも写す**: 反復の地図で「反復」の小節は肉付けまで写す。「変奏」の小節も、参照元の肉付けの型を優先して選ぶ(Compose & Embellish の教訓)。

### 7-3. 読み返しと改稿のループ(粒度の上下)

- **分析器**: 生成した(または人が直した)旋律を、AMRA 方式の最短経路で還元し、骨格を取り戻す。距離の指数 η を変えれば、細かい還元から粗い還元まで何段かの粒度で読める。
- **層ごとの点検**
  - L0: 実際の音域・密度の曲線と計画の差、最高音の回数と位置、終止の位置と種類、反復の地図の実現度。新しい素材の割合が 15〜35% か。
  - L1: 還元した骨格が、それ自体として良い旋律か(順次が主体・弧・終止の音度)。**各層の還元がそれぞれ旋律として成り立つか**という Schenker 的な見方を点検の軸にする。
  - L3: 局所の欠点。今の `critique_melody` の担当。
  - 位置の分布: 句の終わりの主音・長い音の割合が、頭や途中と違うか(Dai 2020・2022)。**違いが無いこと自体を減点する**。
- **改稿**
  1. 誤差が最も大きい層と範囲を選ぶ。
  2. その層の、その範囲だけを作り直す。上の層は固定し、下の層は作り直す(Coconet の「一部を消して書き直す」、MeloForm の句単位の書き直し、Whole-song の半分ずつの塗り直し)。
  3. 全体の費用が下がれば採用する。
  4. N 回、または改善が止まるまで繰り返す。
- **MCP の窓口**(LLM や人が同じループを回せるように)
  - `plan_section`: L0 を返す・直す
  - `get_reduction`: 粒度を指定して骨格を返す
  - `revise`: 層と範囲を指定して作り直す

  WuYun の「段の間で人が骨格を直せる」、Melody Slot Machine の「21.5% は人が足した」のように、**自動生成と人・LLM の加筆の分担**を前提にする。
  - 注意: `Command` の決定性の原則上、乱数の種と新しい ID は窓口の側で決めて渡す。

### 7-4. 避けること

- 骨格を強拍の和音の音だけで作ること(WuYun で最悪級)。
- 緊張や音域の曲線だけを目的関数にし、句と終止を後回しにすること(MorpheuS)。
- 点数の高い 1 案だけを選ぶこと。今の `order_candidates` の考え方と同じく、点数は足切りに使い、通った案は多様に並べる(別レポート metrics.md の Goodhart の議論)。
- 反復の句をそのまま貼るだけにすること。MeloForm の「句の名札だけの反復」は評価が低い。

### 7-5. 最初に試す最小の構成(提案)

1. AMRA の還元(辺の費用 + 重要度 + 最短経路)を Rust で書く。まず分析器として使う。数十行と N² の辺で済む。
2. L0 の最小版として、句の長さ・終止の種類・小節ごとの音域の中心と幅・密度の 4 つを役割の型から作る。
3. 骨格を L0 に沿って動的計画法で選び、今の動機を「骨格の 2 音間の装飾の型」として当てる。
4. 分析器で読み返し、L0 との差が大きい句だけを作り直すループを 3〜5 回まわす。
5. 位置の分布(句の終わりの主音率・長い音率)と新しい素材の割合を `critique` に足す。
