# 曲の設計データ: 画面とデータの流れ(設計)

曲の設計(構成・パートの役割・音域・旋律の計画)を、人と AI が一緒に試行錯誤し、AI の作曲・改稿の作業とつなげるための設計。
2026-10-03 に方針を、2026-10-04 に画面の見た目を決めた。実装は §7 の段階 0 から進める。

## 0. 要旨

- 設計データは **計画** として持ち、人も AI も同じコマンドで直す。計画が唯一の正で、音(クリップ)は計画から作ったもの
- 計画は曲の計画(区間)と **パートの計画**(旋律に限らず、ベース・ドラム・コード・パッドなど全パート)
- 画面はピアノロールに重ねず、別画面 **「設計」** を作る。中心は 3 つ: **曲線**(盛り上がり)・**帯**(パートごとの音域)・
  **表**(区間 × パートの役割)。どれも計画と実測を重ね、直接いじれる
- AI が作った後に人が手で直した所は、作り直しのとき **既定で保護**(残して報告)。上書きしたいときは
  **「手直しも含めて上書き」** のボタン(と、AI への同じ意味の指示)

## 1. 決めたこと(2026-10-03)

| 論点 | 決定 |
|---|---|
| 計画の範囲 | 旋律だけでなく、全パートの計画に広げる |
| 画面の置き場所 | ピアノロールは複雑にしない。別画面「設計」(タイムライン・ミキサーと並ぶ切り替え) |
| 画面で直す深さ | 曲線・帯・表を直接いじれる |
| 手で直した所 | 既定で保護。「手直しも含めて上書き」のボタンを用意する |
| 固定の細かさ | 音 1 つの単位まで持つ(細かく持てば、句・小節・区間の粗い固定はその集まりとして扱える) |
| 役割の段階 | 4 段階では少ない。「働き」と「存在の段階」の 2 つの軸に分け、段階は 6 つ(§3.2) |
| 計画の無い曲 | 今の音から推定する。推定した計画はすぐには正にならず、人が確認して採用する。確認しない設定もある(§3.5) |
| 画面の見た目 | 触れる試作で確かめて決めた(§5.10) |

## 2. 今の作りの課題

1. **区間に ID が無い**: 区間(`Project.sections`)は位置と名前で特定している。マーカーを動かす・名前を変えると、計画との対応が切れる
2. **手直しを見分けられない**: クリップの参照 `plan_refs {id, rev, digest}` は「計画が先に進んだか」しか分からない。作り直すと人の手直しを黙って上書きする
3. **固定の印が無い**: 人の「ここは変えない」を AI の作り直し・改稿に伝えられない
4. **計画の変更が画面に届かない**: 曲の変更は通知している(`ProjectChanged`)が、計画(`plans.json`)の変更は通知していない
5. **計画と実測を並べる口が無い**: AI は数値で比べている(`critique_arrangement` の energy、`analyze_melody` の音域)が、人には見えない

## 3. データ

### 3.0 曲全体の計画

曲 1 つにつき 1 つ(`plans.json` の kind: "song")。区間・パートの計画の上に置く、曲全体の狙い:

| 項目 | 意味 |
|---|---|
| `genre` | ジャンル(言葉) |
| `mood` | 雰囲気の言葉(複数) |
| `key` | キー・旋法(曲のデータの調と別に「狙い」として持つ。推定ではここに入れる) |
| `arc` | 盛り上がりの型(rise 段々に上がる / waves 波を 2 回 / peak 山を 1 つ / sink 沈んでいく / flat 平ら)。「型を曲線に当てる」で区間の曲線に写す |
| `brightness` / `density` / `organic` | 明るさ(暗い〜明るい)・音の密度(まばら〜ぎっしり)・質感(無機質〜有機的)。0〜10。AI が音色・フィルタ・音域・刻みを選ぶ目安 |
| `loudness` | 音量の目標(LUFS) |
| `musts` | 守ること(「リードメロディーは入れない」など。AI の作る・直す道具はこれに反しない) |
| `refs` | 参考曲 |
| `note` | 全体のメモ |

テンポと長さは曲のデータをそのまま使い、計画には二重に持たない。テンポは設計画面でも直せる(曲のテンポを変えるコマンドになり、
タイムラインにもすぐ反映、曲の履歴に残る。途中でテンポが変わる曲は「途中で変わる」とだけ出し、直すのはタイムラインで)。
長さ(小節数)はタイムラインから読んだ値を見せるだけ。拍子は途中で変わる曲を一つの値で表せないので、この画面には出さない。

### 3.1 曲の計画(区間の位置は `Project.sections`、区間の設計は曲全体の計画)

区間の位置と名前(`SectionMarker {id, tick, name}`)は曲のデータで、曲の履歴に残る。区間の設計(盛り上がり `energy`・形 `curve`・
境目 `join`・鳴らすトラック `tracks`・メモ `note`)の持ち主は曲全体の計画(`plans.json` の kind: "song" の `sections`。区間を ID で指す)で、
計画の履歴に残る。曲を読み出すとき(画面・AI の get_project・点検)に、計画の値を区間へ重ねて見せる。設計画面で盛り上がりなどを
直しても曲の履歴は増えず、区間の位置・名前も変えたときは曲と計画の変更を一組にする(曲の側で取り消すと計画も戻る)。
以前の曲(区間の設計を曲に持っていたもの)は、開いたときに曲全体の計画へ移す。

区間の項目:

- `id: SectionId`(`sec_xxxxxx`)。パートの計画・旋律の計画は区間をこの ID で指す(位置・名前が変わっても切れない)
- `curve`(区間の中の盛り上がりの形: 点の列 `[(位置 0〜1, 値 0〜10)]`。両端は必ずある。省略で平ら)
- `join`(次の区間との境目: `smooth` = つなぐ〈この区間の終わりと次の頭を同じ値にそろえる〉/ `step` = 段差〈急に変わる。ビルド → ドロップの
  落差・ブレイクの入りなど〉。推定と既定では、和音・音量・鳴っているパートが大きく変わる境目を段差、ほかをつなぐにする)

`tracks`(鳴らすトラックの名前)は §3.2 のパートの計画の役割へ移す(読み込み時に写す)。

### 3.2 パートの計画(`plans.json` の kind: "part")

トラック 1 本につき 1 つ。区間ごとに:

| 項目 | 意味 | 画面 |
|---|---|---|
| `function` | 働き(トラックの既定 + 区間ごとに変えられる。下の表のキー: beat / bass / sub / harmony / rhythm / lead / hook / answer / texture / ear_candy / transition) | 表の行の名前の下 |
| `presence` | 存在の段階 0〜5: 鳴らさない / 気配 / 背景 / 支え / 前面 / 主役 | 表のマス |
| `register` | 音域の帯: 区間ごとの `[下, 上]`(MIDI のノート番号)。区間ごとに別の値を持てる(全区間まとめて動かす操作もある) | 帯 |
| `density` | 刻みの細かさ(0〜1。音の数の目安) | 表の添え書き |
| `rhythm` | リズムの系統(sustain / pulse / syncopated / busy など。今の旋律の計画と同じ語彙) | 表の添え書き |
| `note` | 意図のメモ(言葉) | パネル |
| `locked` | 固定(この区間のこのパートは作り直さない) | 表のマスの鍵 |

**働き**(作曲・ミックスの解説と、ポピュラー音楽の分析の研究から。Owsinski の 5 つの要素〈土台・パッド・リズム・リード・フィル〉、
Moore の 4 つの層〈拍・低音・旋律・和声の詰め物〉と、のちに足された「目新しさ」の層、ダンス音楽の制作の解説〈フック・つなぎ・質感〉):

| 働き | 例 |
|---|---|
| ビート(拍の土台) | キック・スネア・メインのハット |
| 低音の土台 | ベース |
| サブ | 最低域だけを支える低音 |
| 和声の支え | パッド・コードの持続・刻みの伴奏 |
| リズムの彩り | シェイカー・トップループ・カウンターのリズム |
| 主役 | 歌・リード・前面に出るベース(ワブル) |
| フック | 繰り返す決めの短い動機(リフ) |
| 合いの手 | 主役の隙間を埋めるフィル・カウンターメロディー |
| 質感・空気 | ドローン・テクスチャ・環境音 |
| 飾り | 一度きりの小技(イヤーキャンディ) |
| つなぎ | ライザー・インパクト・ダウンリフター・フィル |

同時に前に出る要素は 3〜4 つまでが目安(Owsinski)。点検で「前面・主役が同時に 5 つ以上」を知らせる。
密度(`density`)は、解説の「活動の度合い」(低・中・高)にあたる。

旋律の計画(kind: "melody"。句・骨格・表情まで持つ)は、パートの計画の詳しい版として残す。旋律のトラックは両方を持ち、
区間の `role`・`register` はパートの計画を正とする(旋律の計画の区間の音域はそこから作る)。

### 3.3 作ったものとの対応

- 計画の参照: `plan_refs[clip] = {id, rev, digest}`(どの計画の、どの版から作ったか)
- 作った時の指紋: `made[clip] = {spans: [{start, end, hash}]}`。AI が作った・直したクリップの中身を、曲の小節の境目で切って
  小節ごとに持つ(位置はクリップの頭から。音の ID と固定の印は指紋に含めない)。計画から作ったかどうかに関わらず、
  AI のすべての編集で記録する(アクターが同じ履歴の 1 件に足す)。AI が中身を変えなかった小節は前の指紋を引き継ぐので、
  人が手で直した小節は、AI が別の所を直した後も「手で直した」のまま。前の指紋はクリップの頭からの位置で引くので、
  AI がクリップを動かしても(小節の区切りが同じなら)手で直した印は残る
- 状態は 3 つを組み合わせる:
  - **計画どおり**: 計画の digest が同じ
  - **計画が先に進んだ**: 計画の digest が違う(作り直せる)
  - **手で直した**: 作った時の指紋と今の中身が違う小節がある(その小節は保護の対象)
- 指紋の記録が無いクリップ(この仕組みより前の曲・人が作ったクリップ)は見分けられないので、手直しは無いものとして扱う
  (AI が書き込むと、そこから記録が始まる)

### 3.4 固定

- 固定(🔒)の意味: **AI が作り直すとき、「手直しも含めて上書き」でも変えない所**。人はいつでも変えられる(人の操作は止めない)
- 音 1 つの単位まで持つ: `Note.locked`(曲のデータ)。区間 × パート(`locked`)・旋律の句・小節の固定は、その範囲の音の固定としても扱える
  (画面では範囲の固定を 1 つの印で見せる)
- 作り直し・改稿の道具はすべて固定を読み、触らない。AI の編集では、固定の音を消す・変える・切る編集に加えて、
  固定の音があるクリップを動かす・固定の音がループの外に出る・音声のクリップに差し替える編集も外す(外したことは応答で知らせる)

### 3.5 計画の無い曲(推定と確認)

- 今の音から計画を推定する。区間は今のマーカー(ID 付き)を使い、パートごとに区間の存在の段階(鳴っているか・音量の順)と
  音域の帯(実際に鳴っている音域)を測った値から決める。働きは、ドラムの音源 → ビート、トラックの名前(Lead・Arp・Riser・Bass・
  Kick など。日本語の名前も)、音の数がごく少ない → つなぎ、低い → 低音、和音が多い → 和声、細かい音が並ぶ → リズム、残りの旋律のうち
  最も前に出ているもの → 主役、ほかは合いの手。曲全体の計画が無ければ、盛り上がりの型(区間ごとの実測)とキーを推定する
- 一度も計画を作っていない曲(音と区間がある)で設計画面を開くと、1 回だけ自動で推定する。計画の無いパートが残っていれば、
  「計画の無い所を推定」でいつでも推定できる(Ctrl+Z でまとめて戻せる)。区間のマーカーが無い曲・音の無い曲では推定しない
- 推定した計画は **未確認の計画**(状態 `estimated`)として保存し、今の計画にはしない。AI は未確認の計画を「参考」としてだけ使い、
  作り直し・点検の基準にはしない
- 画面の上に確認の帯: **この計画を採用** / **直してから採用**(直した版を採用)/ **捨てる**、と **次から確認せずに採用する** の切り替え
  (設定の「推定した計画をそのまま採用する」と同じ。既定は確認する)。AI も「推定して採用まで」をまとめて頼まれたときだけ採用できる

### 3.6 測った値

- 区間ごとの盛り上がり(今の critique_arrangement の energy)、パートごと・区間ごとの実際の音域(下 10%〜上 90% の範囲と中心)、
  実際の役割(鳴っているか・音の数・音量から)、密度
- 測った値は計画と比べ、**ずれ** を指摘として人にも AI にも同じものを見せる(計画では鳴らさないのに鳴っている、帯から外れている、など)

## 4. データの流れ

```
 人(設計画面・チャット)          AI(MCP の道具)
        │  計画のコマンド               │  計画のコマンド
        ▼                               ▼
   ┌─────────── 計画(曲の計画 + パートの計画 + 旋律の計画)───────────┐
   │  履歴: 誰が・なぜ(言葉)・前後の測定                                  │
   └───────┬─────────────────────────────────────────────────┘
           │ 作る(realize。固定と手直しを守る)
           ▼
       曲(クリップ・ノート)──→ 測る(曲線・帯・表の実測)──→ ずれ = 指摘
           ▲                                                   │
           └──────────── 直す(revise)/ 人が手で直す ←────────┘
```

- **同じコマンド**: 画面の操作もコマンド(区間の位置・名前は `set_sections`、区間の設計・パートの計画は計画のコマンド)。人の操作も履歴に「人間」として残る
- **通知**: 計画の変更を画面と AI に通知する(`ProjectChanged` に計画の版を載せる。AI は `plan_log` の since で差分を読む)
- **言葉の記録**: 人の注文(チャット・画面のメモ)は計画の変更の理由(`why`、`trigger: user`)として残す。AI が数値に置き換えた変更も
  同じ履歴に残るので、計画の履歴が対話の記録になる
- **案は枝で**: AI の別案は派生の計画(`derived_from`、状態 `proposal`)として出し(MCP の `propose_design`)、今の計画も曲も変えない。
  案は「今の曲に当てると案の音になる編集の列」(`Plan.patch`)も持つ(出すときに今の曲に試しに当てて確かめ、固定の音は外す。
  当てても今の曲と同じ音になる案は受け付けない)。出したときに、案の編集が触る所(トラック・クリップ・エフェクト・テンポなど)の
  中身の指紋(`Plan.patch_base`)も持ち、案のまま名前や中身を保存し直しても案の音と指紋は引き継ぐ。
  聴き比べは今の A/B の仕組みを広げ、今の曲と「今の曲に案を当てた曲」をメモリの上で描き出し、音量をそろえて切り替える。
  採用すると案の音を曲に当て(1 件の編集。AI の音として指紋も残し、固定の音は守る。外した編集は知らせる)、
  案の中身が元の計画の新しい版になる(元が無ければ案が今の計画になる)。
  同じ元の計画から出たほかの案、同じきっかけ(人の同じ頼み。出した時刻が近いもの)で出たほかの案、いっしょに聴き比べていた案は、
  採用と同時に捨てる(計画の履歴に残るので取り消せる)。
  採用は「曲の編集 1 件」と「計画の変更の一組」で、計画の側の変更には一組の曲の編集を記録する(経緯の `song_entry`)。
  曲の側でその編集を取り消す・やり直すと(設計画面・タイムラインの Ctrl+Z / Ctrl+Y、履歴パネルの「この変更だけ取り消す」、
  チェックポイントまで戻す、AI の undo)、計画の側の一組も「この変更だけ取り消す」の形で一緒に戻る(後から入った計画の別の変更は残り、
  戻したことも計画の履歴に残る)。一組の計画の変更を計画の側だけで取り消す・やり直すことはしない(曲と食い違うので。
  計画の履歴では一組だと示し、「この変更だけ取り消す」を出さない)。
  設計画面の Ctrl+Z は、ほかの画面で戻した・やり直した操作に合わせて覚えを並べ直す。
  案を出した後に、案の触る所が直された案(指紋が違う)と、曲が変わって当てられなくなった案は、手直しを案で上書きしないよう
  採用・聴き比べをせず、理由を出して AI に作り直してもらう
- **作り直しの約束**(全部の作る・直す道具で共通):
  1. 固定の所は触らない
  2. 手で直した範囲は残す(既定)。残した所と作り直した所の境目は、つなぎ目だけ整える
  3. 報告に「残した所」を書く(応答の `protected`)
  4. `overwrite_edits: true`(画面の「手直しも含めて上書き」のボタン)のときだけ、手直しも作り直す。固定はそれでも触らない
- **作る道具は計画を目安にする**: `write_bassline`・`write_chords`・`write_arpeggio`・`write_melody`・`write_drums` は、トラックに
  採用済みのパートの計画があれば、鳴らさない区間(存在の段階 0)・固定の区間には書かず、区間ごとに音域の帯へ寄せる
  (まず区間の音をまとめてオクターブで動かして旋律の形を保ち、外れる音だけを折り返す。ドラムは区間だけ)。範囲を指定しなければ帯で作る。
  合わせた所は応答の `plan` に出る。推定の計画と案は目安にしない。`follow_plan: false` で計画を見ずに作る

## 5. 画面「設計」

タイムライン・ミキサーと並ぶ切り替え。横軸は曲の小節。設計は曲全体を見渡すことが多いので、横の縮尺はタイムラインと別に持ち、
既定は曲全体が見える幅(「全体」)。拡大・縮小のボタンで変える。

### 5.0 曲全体

- 画面のいちばん上の段。ジャンル・雰囲気の言葉・キー・テンポ(タイムラインと同じ値)・長さ(読むだけ)・盛り上がりの型・明るさ・密度・質感・音量の目標・
  守ること・参考曲・全体のメモを並べ、その場で直せる。段の中か見出しの「全体を選ぶ」でパネルに「曲全体」(メモ・「型を曲線に当てる」)

### 5.1 曲線(盛り上がり)

- 区間ごとの盛り上がりの計画(0〜10、区間の中の形)と、実測を重ねる。ずれの大きい区間に印(実測は表示を切り替えられる)
- 縦軸: 0 と 10 は実線で示し、範囲の外は暗く塗る。左の列に 0〜10 の数字だけを出す(「最小・最大」や「energy」の文字は出さない)
- 実測とのずれの印の役目: 計画と実際の音が食い違っている区間を、人と AI の両方に見せる(AI が作った後・人が手で直した後・
  曲線を動かした後に起きる)。直すのは計画か音のどちらか(計画を実際に合わせる / 音を計画に合わせて作り直す)。点検も同じものを使う
- 操作: 点をドラッグ(上下で値、間の点は左右にも)、ダブルクリックで点を足す、右クリックで消す(両端は消せない)。
  境目の印をクリックで「つなぐ / 段差」。つないだ境目は、片方の端を動かすと隣の端も一緒に動く
- 印の説明: 左の列(軸の数字の左)に、線(計画・実測)と印(つなぐ・段差・ずれ)を 2 つに分けて並べ、0〜10 の範囲の縦の真ん中にそろえる
  (乗せると詳しい説明)。軸の数字との間に細い線。実測を隠すと実測とずれは薄く
- 平行に動かす: 区間の面を上下にドラッグでその区間ごと(つないだ隣の端も一緒に)、Shift + ドラッグで曲線全体。
  上の道具で「全体を上げる / 下げる」(0.5 ずつ)と「起伏 ＋ / −」(平均を中心に起伏を大きく・小さく)
- 効き方: AI が作るときの目安(旋律の音域の高さ・広さ、ドラム・コードの刻み、パートの抜き差し)と、点検の比べる先が変わる

### 5.2 帯(パートごとの音域)

- 選んだパートの帯だけを色付きで前に出し、ほかのパートは薄い輪郭だけ(触れない)。実際の音の範囲を線で重ねる
- パートの選び方: 帯の段の左の一覧か、表のパートの名前(帯は全部の音高が見えているので、選んでも段の中はスクロールしない)
- 操作: 区間ごとに上下にドラッグ(移高)、上下の端で幅。Shift を押しながらで全区間まとめて
- まとめての操作(上の道具): 対象を「選んだパートの全区間」か「全パートの全区間」から選び、半音・オクターブで上げ下げ、
  幅を広げる・狭める(中心はそのまま)
- 重なり: 違う楽器の音域が重なるのはふつうのことなので、警告にはしない。「重なりを薄く表示(参考)」で斜線を出せる(既定は出さない)。
  気にするのは低域(C3 より下)で前に出る 2 つのパートが重なるときだけで、パネルに参考として出す(キックとベースの住み分け)
- 旋律のパートを選ぶと、横のパネルに句の並び(A・A′・B)と骨格を出す(句の長さ・固定もそこで)

### 5.3 表(区間 × パート)

- マスに存在の段階(5 本の目盛りと名前: 鳴らさない〜主役)、行の名前の下に働き。実際とずれたマスに印、固定のマスに鍵、メモのあるマスに吹き出し
- 操作(クリックで順に切り替える方式はやめた): マスのクリックは選ぶだけ。役割を変えるのはマスの右の ▾ ボタン(選んだマスと、マウスを乗せた
  マスに出る)で、選択肢(段階 0〜5 と説明・働き・固定)をマスの下(入らなければ上)に、マスを覆わずに出す。
  開いている間はボタンが ∧ になり、もう一度押すと閉じる(ほかの所を押しても閉じる)。選んだマスで数字キー 0〜5、
  マスを押したまま横へドラッグで同じ段階を塗る(固定のマスは塗らない)

### 5.4 横のパネル(インスペクタ)

- 選んだ区間・パート・句の設定、その所のメモ、測った値とのずれ
- ボタン: **この版から作り直す** / **手直しも含めて上書き** / **この所について AI に頼む**(下のチャットの入力欄へ。対象は添え済み)
- パネルは中で縦にスクロールする(メモが多いときはメモの欄だけでもスクロール)

### 5.5 意図を言葉で(メモとチャットを分ける)

- **メモ**と **AI とのやりとり**は分ける。メモは「所」に付く人の言葉、やりとりはどの画面でも同じ 1 本のチャット
- **メモ**: 区間・パート・マス(区間 × パート)・段の全体に付ける人の言葉(いつ)。パネルの「メモ」に並び、付いた所には吹き出しの印。
  曲全体の計画の `memos`(`{target, text, when}`。target は song / section:<区間 ID> / part:<トラック ID> / cell:<トラック ID>:<区間 ID> /
  curve など)に残り(曲全体の計画が無ければ作る)、AI はその所を作る・直すときに読む。AI はメモを書かない(AI の判断の理由は計画の履歴の `why` に残る)
- **AI に頼む**: チャットで頼む。設計画面で選んだ所が、チャットの入力欄に「対象」として自動で添わる(今の【対象範囲】の仕組みを広げる。
  × で外せば曲全体への指示)。対象の所のメモも AI に渡る。
  パネルの「この所について AI に頼む」は入力欄へ移るだけ
- **段の全体を選ぶ**: 見出しの **全体を選ぶ** で、その段の全体を対象にする(曲全体・盛り上がり全体・音域全体〈全パート〉・役割全体。
  区間の段は左の「区間」の横で、区間の構成全体)。「盛り上がり全体をもっとメリハリのある形に」のような頼み方のため。
  選ぶと「全体を選択中」に変わり、段の枠が強調される。もう一度押すと選択を外す(何も選んでいない状態。AI への指示は曲全体が対象)。
  畳んだ段でも出しておき、畳んだまま対象にできる。パネルにはその段全体の要約(いちばん高い区間・段差・ずれなど)を出す
- **返答の出る所**: チャット欄(考えている間の表示 → 何をどう直したか)。直した結果は計画の新しい版になり、履歴の欄に「新しい」の印で載る。
  返答の「その所を見る」で設計画面の該当の所を選ぶ。頼んだ言葉は版の理由(`why`、`trigger: user`)として残る

### 5.6 計画の履歴と取り消し

- 下の履歴の欄に「計画の履歴 / 曲の履歴」のタブ。設計画面では計画の履歴を先に出す(版の一覧。曲の履歴とは別。誰が・なぜ・前後の測定)
- 設計画面にいる間の Ctrl+Z / Ctrl+Shift+Z(と上の取り消し・やり直しのボタン)は、設計画面で直したものを戻す。区間の盛り上がり・
  境目・テンポは曲のデータなので曲の履歴に、ほかは計画の履歴に残る。設計画面は直した先を覚えておき、その履歴を戻す(覚えが無ければ計画)。
  計画を取り消しても音はそのまま(クリップの印が「計画が先に進んだ」になり、作り直すかを選べる)
- 版ごとに **この版に戻す**(戻したことも新しい版として残る。壊さない)、**この変更だけ取り消す**(後の変更は残す。今の `undo_plan` の revert)
- 案(枝)は設計画面の上の「AI の案」の帯に並べ、**聴き比べる**(A 今 / B 案)/ **採用** / **捨てる**。案ごとに「変わる所」
  (案を当てた曲との音の違いから割り出した区間。トラックの音色・音量の違いはそのトラックが鳴っている区間、マスター・テンポなど
  曲全体に効く違いはそう書く)を出し、区間を押すとその区間で聴き比べる。案が 2 つ以上あれば **まとめて聴き比べる**
  (A 今 / B・C … 案。今と案 4 つまで、いちばん小さい音量にそろえ、範囲はいちばん多くの案が変わる区間)。
  範囲を選ばずに聴き比べると、変わる所の最初の区間を聴く(選んでいる区間が変わる所ならそこ)。聴き比べ中は範囲をループにし、
  A / B はいつでも切り替えられる(止まっている・範囲の外なら範囲の頭から鳴らす)。範囲の中で今と案の音が同じなら、そう知らせる。
  計画の履歴では案の行を「案」と書き、「この版に戻す」は出さない

### 5.7 色

- パートの色は、タイムラインでトラックに付けた色(`Track.color`)。付けていなければ既定の灰色
- 画面全体は灰色を基本にし、強調色は選んだ所(区間・パート・マス)と計画の線だけに使う。パートの色は名前の横の小さな印と、選んだパートの帯だけ

### 5.8 ほかの画面との連動

- タイムラインのクリップに状態の印(計画が先に進んだ / 手で直した小節の数 / 固定の音の数。計画どおりで何も無ければ小さなチェック)。
  クリップの名前の後ろに置く(長いクリップの右端は画面の外に出るため)。押すと設計画面のそのパートへ
- チャットと履歴は、ほかの画面と同じく画面の下(左にチャット、右に履歴。高さの仕切り・隠すボタンも同じ)。画面を切り替えても会話はそのまま
- チャット: 設計画面で選んだ区間・パート・句を、AI への指示の対象(今の【対象範囲】の仕組みを広げる)として添える

### 5.9 画面の作り

- アプリのほかの画面と同じく、画面の高さに収める(ページ全体はスクロールしない)。上から 曲全体・区間・曲線・帯・表、右に詳細パネル、下にチャットと履歴
- 区間・曲線・帯・表は段に分け、段ごとに見出しの帯と枠を付ける(切れ目を見やすく)。操作の説明は見出しの「?」にまとめる
- 曲全体の段と、区間に沿った段(区間・曲線・帯・表)は分ける。区間に沿った段は「区間ごとの計画」の 1 つの枠にまとめ(地の色も少し変える)、
  曲全体の段とは間を空ける。曲全体は時間の流れを持たないので、横のスクロールにも加わらない
- 「区間ごとの計画」の枠の中は縦にスクロールする。縦のスクロールはこの枠の 1 つだけにし、段の中には持たせない(入れ子にするとホイールを
  内側が先に受け取り、枠がスクロールしなくなる)。枠の見出しと区間の名前は上に、横のスクロールバーは下に貼り付けて、スクロールしても見える
- 折りたたみの印は線の山形(畳むと右向き)で、押しやすい大きさにする
- 画面の見出しは中身の名前にする: 曲線 →「盛り上がり」、帯 →「パートごとの音域」、表 →「パートの役割」。全体を選んだときの対象の名前も
  「盛り上がり全体」「音域全体(全パート)」「役割全体」(この文書の「曲線・帯・表」は形の呼び名として残す)
- 曲全体・曲線・帯・表は、見出しの帯(か ▾)をクリックで折りたたみ / 展開(畳むと見出しの 1 行だけ。曲全体は畳むと要約を 1 行で出す)。
  見出しの帯のクリックは折りたたみだけ(選択は変えない)。見出しの中の道具のボタン・チェック・「?」・「全体を選ぶ」では畳まない。
  畳んだ段は中身が見えないので、中身への操作(道具のボタン・凡例・説明の「?」)は出さない。開け閉めは覚えておく
- ドラッグ中は文字を選ばない
- 左の名前の列は横にスクロールしない。横は 1 本のスクロール(と Shift + ホイール)で全段がそろって動く
- ドラッグで動かすのは左ボタンだけ(ホイールの押し込み・右ボタンでは動かさない)。曲線の点はダブルクリックで足し、右クリックで消す
- 曲線・帯・表は、下の端のつまみで高さを変える(ダブルクリックで元の高さ)。曲線は 0〜10 の縦の大きさ(最小は既定の高さ)、
  帯は音高の縦の大きさ。表は行の高さ(24〜64px。低くすると働きの小さな文字は隠す)で伸び縮みし、24px × パートの数より
  小さくすると段の中でスクロールする。パートが多い曲は枠のスクロールで見る。帯の音高の目盛りは中身の左に重ね、横には動かない
- 縮めるときは枠の下に一時的な余白を足し、枠のスクロールが詰まってつまみがカーソルから離れないようにする(余白は上へスクロールすると消える)
- ドラッグは、画面の外でボタンを離して終わりの知らせが届かなくても、戻ってきたときにボタンが離れていれば終える(取り残さない)

### 5.10 モック

見た目の試作(触れる): ダークでインダストリアルな曲(7 区間・96 小節)を例に、曲全体・区間ごとの計画(盛り上がり・音域・役割)・
詳細パネル・推定した計画の確認の帯・下のチャットと履歴を、触って確かめながら直し、見た目と操作を決めた(2026-10-04)。
§5.0〜5.9 はその結果。段階 1・2 の画面はこれに沿って作る。

## 6. AI の道具の変更

- `get_design`(段階 0 で作った): 曲全体の計画・区間(ID・形・境目と測った盛り上がり)・パート × 区間の計画と測った値・
  ずれ・クリップの状態(計画どおり / 先に進んだ、手で直した小節、固定の音の数)と、働き・段階などの語彙をまとめて返す
- 計画を直すのは今ある道具で: 区間は `set_song_plan`(id・curve・join を足した)、曲全体・パートは `save_plan` / `edit_plan`
  (kind song / part、state estimated / adopted)。区間の置き換えでは、ID の無い区間に今の区間の ID を名前 → 位置の順で引き継ぐ
- 新しい道具(案): `edit_design`(曲線・帯・表の値をまとめて変える。why 必須)、`realize_part`(パートの計画からそのパートを作る・作り直す)
- 今の作る道具(write_drums・write_chords・write_bassline・write_melody・plan_melody・realize_melody・revise_melody・
  write_wobble など)は、パートの計画があればそれを目安にする(段階 1 以降)。§4 の作り直しの約束のうち、
  固定(AI のすべての編集で外す。外した編集は応答の `kept_locked`)と指紋の記録は段階 0 ですべての道具に効く。
  手直しを残す作り直し(応答の `protected`、`overwrite_edits` で上書き)は、クリップを差し替える realize_melody・revise_melody から
- 案内(get_guide)に「設計から作る」流れ: 曲線と表を先に決める → 帯 → 各パートを作る → 測って、ずれを直す(計画か音のどちらかを)
