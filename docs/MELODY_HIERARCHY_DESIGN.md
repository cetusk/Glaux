# 旋律を「上から下へ」作り、粒度を行き来して直す ― 設計(2026-09-30)

## 0. 要旨

- 今の write_melody は「1〜2 小節の動機を並べて局所的に変形する」1 回きりの生成。作曲者の指摘は 4 つ:
  (1) 全体のリズムの輪郭が変わらない、(2) 局所の微調整は全体から浮く、(3) 前後の文脈に流れるように乗らない、
  (4) 音域が一定で特徴が無い。さらに (5) 人は様々な粒度で何度も譜面を行き来し、読み返し・聴き返してフィードバックのループを回している。
- 調査(docs/melody_research/ の hier_generation・composing_process・iterative)はそろって同じ方向を示す:
  **計画(区間の波)→ 骨格 → 肉付け** の上から下への生成と、**上の粒度から直し、局所は前後の文脈ごと直し、
  直らなければ上へ戻る** 改稿のループ。
- 設計の柱:
  1. **4 つの層**: L0 区間の計画(音域の軌跡・密度の曲線・句の長さと終止・繰り返しの地図・前後の受け渡し)/
     L1 句の骨格(2 拍に 1 音ほどの要の音)/ L2 句のリズム / L3 表面の音(骨格の間の装飾)。
  2. **分析器を先に作る**: どの旋律(人が書いた・読み込んだ・生成した)からも同じ層を取り出して測れるようにする(旋律の還元)。
     測る側が正確でないと直すループは回らない(Self-Refine の失敗の 94% は批評の誤り)。
  3. **粒度ごとの点検と「見る」道具**: 小節・句・区間・曲で測り、LLM が読む要約と、人が見る表を返す。
  4. **直す道具**: 層と範囲を指定して、その層から下だけを作り直す。境目をなじませ、繰り返しの関係を追従させ、
     悪化しないときだけ採用。粒度ごとに最大 3 回、最良を残す。
  5. **計画は編集できるデータ**: AI や人が「ここで一度下げて」「後半は広く」と直してから作り直せる。

## 1. 問題の分析(今の作り方のどこが原因か)

| 作曲者の指摘 | 今の作り方の原因 | 調査の対応する知見 |
|---|---|---|
| (1) 全体のリズムの輪郭が変わらない | 動機のリズムを区間の長さぶん繰り返す。変形は小節の中だけ | 人は区間ごとにリズム(音価・句の長さ・句の始まりの位置)で対比を作る。「歓喜の歌」の改稿は単調なリズムを退けた |
| (2) 局所の微調整が全体から浮く | 変形は前後を見ずに当てる。全体の計画が無い | 局所に閉じるのは初心者の特徴(Colley 1992、Sommers)。局所の直しは前後の文脈ごと・先の目標を見て(Anticipatory MT: 先を見ないと 5 勝 45 敗、見ると 18 勝 11 敗) |
| (3) 前後の文脈に乗らない | 区間を単独で作る。前の区間の終わり・次の区間の頭・ほかの楽器を見ない | 通しの下書きを先に作り、区間を作るときは前後を文脈として渡す(ベートーヴェン、AI Song Contest) |
| (4) 音域が一定 | 役割ごとの固定の音域に閉じ込め、山以外を押し下げ、はみ出しはオクターブで折り返す | 区間ごとの音域帯の割り当て(Stolpe「次の区間で旋律を持ち上げる」)。句ごとの平均音高と幅の計画は守れて好まれる(MeloForm 92.5%) |
| (5) 1 回きり | 案の足切りと選択だけで、測って直すループが無い | 人は「全体 → 部分 → 全体」を往復(Wiggins 1994)。熟達者は小さく直して短く聴き、聴く範囲を広げる(Nash & Blackwell 2012) |

加えて、**句と区間の位置で音の分布が変わらない**ことも AI らしさの兆候(Dai ら: 句の終わりは長い音、全音符以上の 72% が
区間の最後の句の終わり。主音で終わる確率は句の終わりで 35%、ほかで約 20%。深層モデルはどこでも 20〜21% で平ら)。

## 2. 層と表現

### L0 区間の計画(SectionPlan)

区間(`set_song_plan` の区間)ごとに:

| 項目 | 内容 | 既定の決め方 |
|---|---|---|
| `register` | 音域の中心と幅の軌跡(句ごと、または 2 小節ごとの点列)。区間で最高音 1 回 | 盛り上がり(energy)と前後の区間から。山の区間は中心を 3〜7 半音上げ、幅 12〜17 半音(ジャンルの参照から) |
| `density` | 密度の曲線(1 拍あたりの音の数、句ごと) | 疎 → 密 → 解放。energy と役割から |
| `phrases` | 句の並び: 長さ(揃えすぎない。2+2+4、4+4、3+5 など)・始まりの位置(弱起)・ラベル(A A′ B A″)・終止(開く / 閉じる)・終止の音度 | 形式の型(sentence・period・AAAB・SRDC)から |
| `repeat` | 繰り返しの地図: 句 A′ は「A への参照 + 変換(移高・末尾の差し替え・リズムの分割/統合)+ 変奏の距離」。新しい素材は 15〜35% | 形式の型から |
| `rhythm_family` | リズムの型の系統(伸ばす中心・刻む中心・シンコペーション多め・休み多め)。区間どうしで対比 | 役割とジャンル、前後の区間 |
| `handoff` | 前の区間の最後の音・音域 / 次の区間の最初の音への受け渡し(引き継ぐ・跳んで入る・弱起) | 前後の区間の旋律があればそこから |
| `context` | ほかの楽器の混み具合(拍ごとの音の数)と音域の占有 | ほかのトラックの音から |

### L1 句の骨格(Skeleton)

- 要の音の列: おおむね 2 拍に 1 音(全体の約 3 割。WuYun では約 34% が最良、14% は少なすぎ、63% は多すぎ)。
  強拍だけでなく、長い音・シンコペーションの音を混ぜる(強拍だけの骨格はランダムより悪かった)。
- 句の頭・山・終わりの音(着地音と長さ)を先に決め、中を動的計画法で選ぶ。費用は `register` の軌跡からのずれ、
  音程の費用(旋律の還元の辺の費用: 同音 0.1・2 度 0.3・同じ和音の分散 1.5 などを生成向けに流用)、和音との関係、
  前後の骨格との関係(問いと答えで輪郭を変える、A′ は A の骨格から変換)。

### L2 句のリズム(Rhythm)

- 句ごとに、`density` と句の役割から打点の列を作る。**小節の型の繰り返しではなく句の単位**で作る
  (リズムの動機は保ってよいが、句の中での位置・長さ・終わりを句ごとに決める)。
- 句の終わりは長い音(句の終わり ≈ 5 割、区間の終わり ≈ 9 割が目安)。句と句の間に休み(ジャンルの目安)。
- ほかの楽器の混んでいる所を避け、空いている所に入る(掛け合い)。

### L3 表面の音(Surface)

- 骨格の 2 音の間を、リズムの打点に合わせて装飾の型(経過音・刺繍音・分散和音・先取り・掛留)で埋める。
  **今の「動機」は「骨格の 2 音の間に掛ける装飾の型」として持ち直す**(同じ性格を保ちながら、輪郭は骨格に従う)。
- 表情(ビブラートは長い音だけ、食い、強弱)は最後に。

### 繰り返しの結び付け

A′・A″ は A への参照と変換として持ち、A を直したら追従させる(MorpheuS)。区間の 2 回目(ドロップ 2 など)も
前の区間への参照と「どう変えるか」(音域を上げる・リズムの系統を替える・新しい素材)として計画する。

## 3. 分析器(どの旋律からも層を取り出す)

- **旋律の還元**: 表面の音から骨格を取り出す。最短経路による還元(Wang ら ISMIR 2025。辺の費用と音の重要度だけで動く。学習無し)を
  Rust で実装。GTTM のタイムスパン還元の規則も参考にする。
- **句の区切り**: 休み・長い音・骨格の終止・繰り返しの境目から。休みで区切れなければ 4 小節ごと(今の点検と同じ)。
- **区間の計画の推定**: 句ごとの音域の中心と幅・密度・リズムの系統・繰り返しの地図(似た句の対応。編集距離)を推定する。
  → 人が書いた旋律・読み込んだ MIDI・参考曲の譜起こしにも同じ計画が得られる。参考曲の計画は目標の曲線になる。

**最初の一歩はここ**(調査の提案と同じ): 分析器を作り、まず点検と「見る」道具として使う。生成より先に、測る側を正確にする。

## 4. 測る(粒度ごとの点検)

| 粒度 | 測るもの |
|---|---|
| 小節 | 強拍の和音の音、跳躍と戻り、驚き、往復、リズムの面白さ(自己相関) |
| 句 | 骨格の輪郭の型、山の位置、音域、句の終わり(着地音・長さ)、息継ぎ、句の境目の音程と音域の段差、次の句への導き |
| 区間 | 音域の軌跡(中心・幅・最高音)、密度の曲線、リズムの系統とその句をまたぐ似すぎ(リズムの輪郭の自己相似)、緊張の曲線、計画とのずれ |
| 曲 | 区間どうしの対比(音域の中心の差・密度の差・リズムの系統の違い)、山の区間、3 つの時間幅の反復の強さ、同じラベルの句の似かた ÷ 全句の似かた、A と A′ の距離が目標の範囲か、位置による音の分布の差(句の終わりの長さ・主音) |

- 値は「目安の範囲からの外れ」と「参照曲の分布の中の位置」で出す。単一の点を最大化しない(Goodhart)。
- 悪い例(今回のリード、全句が同じリズムの輪郭、音域が一定)が合格しないことをテストで先に保証する。

## 5. 直す(改稿のループ)

1. **計画**: 作曲者の言葉・参考曲・曲の計画書から L0 を作る(幅優先: 全区間 → 各区間の句 → 各句の骨格)。兄弟を見て対比を付ける。
2. **通しの下書き**: 全区間を粗く最後まで作る(骨格 → リズム → 表面)。区間を作るときは前後の区間とほかの楽器を文脈に渡す。
   句ごとに複数の候補を作り、「前とのつながり」と「計画への合致」で選ぶ。
3. **測る**: 全粒度で測り、**上の粒度から**問題を並べる(区間の対比 → 句の構造 → 句の境目 → 小節)。
4. **直す**: いちばん上の粒度の大きい問題 1 つに、安い手から当てる(変数近傍探索)。
   - 区間の手: 移高(3 度・4 度・5 度・オクターブ)、リズムの系統の差し替え、密度、区間の句の作り直し
   - 句の手: 骨格の選び直し(着地音と山を固定して中を選ぶ / 輪郭を替える)、A′ の変奏の距離、終止、息継ぎの位置、答えだけ作り直す
   - 小節の手: 1 音の音高、入れ替え、経過音・刺繍音の挿入と削除、分割と統合、先取り
   - 手の後に必ず: **境目をなじませる**(直した範囲の両隣 1 小節で、リズムと骨格は保ち、境目の 1〜2 音を前後へ滑らかにつながる音に選び直す)、
     **繰り返しの追従**(A を直したら A′ を関係どおりに作り直す)
5. **受け入れ**: 直したかった観点が良くなり、ほかの観点が許容幅を超えて悪くならないときだけ採用。局所解なら区間の 1 割強を振り直す。
6. **上へ戻る**: 変更が区間の境界に触れた・全体の指標が計画から外れた・同じ箇所を 2〜3 回直しても良くならない → 1 つ上の粒度へ。
   下で解けない問題は計画を書き換える。良い着想が出たら計画の方を書き換えて他の区間に波及させる。
7. **止める**: 粒度ごとに最大 3 回(改善は初めの 2〜4 回に集まる)、全体で 8〜10 手ほど。「欠点が無い」ではなく
   「計画が満たされ、直近の周で上の粒度の問題が出なくなった」で止める。最良の版を残す。解けない問題は印を付けて保留し、報告する。
8. **距離を置いた評価**: 最後に、作業中の文脈を持たない別の評価役(新しい文脈の LLM か規則の全体点検)で通しで評価する。

## 6. 人と AI の役割

- **LLM**: 作曲者の言葉を計画の数値に訳す。粒度ごとの要約(「サビの音域の中心がヴァースと同じ」「全句で同じリズムの輪郭」
  「句 3 の終わりが次の句の頭から 9 半音離れている」)を読み、**直す手の名前と引数**で方針を返す。候補から意図に合うものを選ぶ。
  **音を直接書かない。外部の測定なしに良くなったかを判定しない**(LLM の自己判定だけでは悪化する)。
- **人**: チェックポイントで聴く(区間の計画の段・通しの下書きの段・直した後)。原案を残して 2〜3 案を比べる。言葉で方向を伝える。
- **決定性**: 生成と直しは seed で決まる。すべての編集は Command を通し、ループの 1 手 = コマンドのまとまり 1 つ(undo・checkpoint がそのまま使える)。

## 7. 道具(MCP)の形(案)

| 道具 | 入力 | 出力 |
|---|---|---|
| `analyze_melody`(新) | トラック / クリップ / 範囲 | 層の分析: 区間の計画の推定(音域の軌跡・密度・句・繰り返しの地図)、句の骨格、句ごとのリズムの輪郭、粒度ごとの点検、LLM 向けの要約 |
| `plan_melody`(新) | 区間(曲の計画書)、ジャンル・役割、言葉からの目標、参考曲、前後の文脈 | 編集できる計画(JSON)と、その見え方(区間ごとの音域の軌跡・密度の表) |
| `realize_melody`(新。今の write_melody の中身を置き換え) | 計画、どの層から作り直すか、固定する句 | 置いた旋律、案、各層の結果 |
| `revise_melody`(新) | 範囲、粒度、手(名前と引数)か目標、強さ | 直した旋律と、測り直した粒度ごとの差 |
| `critique_melody`(拡張) | `level`(bar / phrase / section / song) | 粒度ごとの曲線と指摘 |
| `write_melody`(残す) | 今と同じ | 内部で plan → realize → 測る → 直す(最大 N 回)を回す手早い入口 |

計画は曲とは別の履歴を持って保存する(§9)。

## 8. 評価

- **回帰の悪例**: 今回のハウスのリード(ドロップ 1・2)、全句が同じリズムの輪郭の旋律、音域が一定の旋律が合格しない。
- **参照**: 参考曲・手持ちの MIDI から計画を推定し、ジャンルの目安の範囲(区間の音域の幅・区間どうしの対比・句の長さの分布・休み)を作る。
- **聴き比べ**: 手元の試作曲のドロップ 1・ブレイク・ドロップ 2 で、今の write_melody の案と新しい方式の案を作曲者に聴き比べてもらう。
  「AI っぽさ」「波に乗っているか」「特徴」を聞く。

## 9. 計画の保存と履歴(2026-09-30 に決定: 保存する。曲とは別に履歴を持つ)

Glaux の履歴は git を見本にしている。計画は「曲とは別のリポジトリ」として持ち、両者を git のサブモジュールのように結ぶ。

| git | 曲(今) | 計画(新) |
|---|---|---|
| 作業ツリー | `project.json` | `plans.json`(全計画の今の状態) |
| コミットの列 | `history.jsonl`(Command と逆コマンド) | `plans.history.jsonl`(PlanCommand と逆コマンド) |
| 起点 | `history.base.json` | `plans.base.json`(同じ仕組み) |
| reset / revert / tag | undo・redo / revert_entry / checkpoint | 同じ操作を計画だけに(曲の undo は計画を戻さず、計画の undo は音符を戻さない) |
| サブモジュールの参照 | ― | クリップの `plan: { id, rev }`(どの計画の、どの版から作った音符か)。`project.json` 側に保存し、曲の履歴に乗る |
| status(作業ツリーとの差) | ― | クリップの `rev` と計画の今の版が違えば「計画が先に進んでいる(作り直し待ち)」 |
| branch | ― | 別案 = 計画の派生(`derived_from: { id, rev }`)。案を並べて比べる |
| diff | ― | 2 つの計画(や版)の差を句・骨格の単位で |

- 計画の中身(`MelodyPlan`)は型を持った JSON: ジャンル・役割・seed・句(長さ・始まり・ラベル・参照と変換・終止・音域・密度・リズムの系統)・
  受け渡し・骨格・文脈の要約。無くてもよい項目は省略し、古い計画も読める。
- 計画の編集(`PlanCommand`): 計画を作る・消す・丸ごと置き換える・一部(JSON Pointer の道)を置き換える。すべて絶対値で、逆コマンドを持つ。
  新しい ID は作る側が生成する(決定性)。可逆性はランダムなコマンドの試験で確かめる(今の `tests/history.rs` と同じ)。
- **コミットメッセージ**(2026-09-30 追加): 計画の履歴の 1 件は、件名(今の `label`)・作者に加えて、本文(なぜ変えたか)・
  きっかけ(作曲者の言葉 / 点検の指摘 / 聴き比べの結果)・変更前後の測定(例: 区間の音域の幅 8 → 13 半音)・親(派生元の計画と版)を持つ。
  log(経緯を読む)・blame(句ごとに、どの変更がなぜその値にしたか)・効果の確認(良くならなかった変更を revert の候補に)に使う。
  計画を変える道具は「なぜ」を受け取る(AI には必須、人の操作では省略可)。曲の側の履歴への本文の追加は別に扱う。
- 実装: `History` / `HistoryEntry` をコマンドの型について汎用にし(既定は今の `Command`)、計画用のセッション(`PlanSession`)を作る。
  保存(`Store`)は同じ追記・切り詰め・裏の書き込み・起点・復旧を使い回す。アクターは曲と計画の 2 つのセッションを持つ。
- 作り直し(`realize_melody`)は曲の Command(音符の置き換えとクリップの `plan` の参照)として 1 手で積む。計画を先に直してから作り直す、
  作り直した音符を気に入らなければ曲の undo で戻す(計画は残る)、計画の undo で前の計画に戻してから作り直す、がそれぞれ独立にできる。

## 10. 段階的な進め方

| 段階 | 内容 | 確かめ方 |
