# AI の音楽表現と音作りを「本格的」にするための調査(2026-09-27)

Glaux の AI は、道具が 53 個(調査の時点)に増え、ミックス・マスタリングの力も上がった。次の目標は、
**本格的なサウンドで、聴いて音楽的な曲を作れること**である。

この文書では、まず今の AI の作曲・演奏表現・音作りの弱点を、実際に作った曲から洗い出す。
続いて、次の 4 つの領域を網羅的に調べ、何をどの順で足すと効くかをまとめる。

- 表現力を上げる技法
- 道具
- 音源
- 研究

対象は**電子音楽・ポップス・グルーブのある音楽**とし、録音・歌は扱わない。
数値の多くは出典付きで、出典が見つからない経験則にはそう書く。

## 0. 要旨

1. **弱点は「足りない機能」より「使われない・手で書くには手間すぎる」こと。**
   AI が作った曲は、ノートがほぼ 16 分の格子どおりに並び、オートメーションは 0 本、強弱もほぼ平らだった。
   道具はあるのに使われていない。
2. **研究でも製品でも、答えは同じ方向を向いている。** LLM に音符を 1 つずつ書かせるのではなく、次の形がうまくいっている。
   - **計画 → 骨格 → 表情 → 批評 → 修正**の多段の流れ
   - **少数の意図の引数**(複雑さ・強さ・フィル・スウィングなど)を受け取り、決まった手順で正確に展開する道具
   - 例: Logic の Session Players、Ableton Live 12 の MIDI Tools、ComposerX、TOMI
3. **グルーブは「ランダム」より「系統的な型」。** 人間らしさの研究では、次のことが分かっている。
   - 楽器ごと・拍の位置ごとの決まったずれと強弱の型が効く。
   - 揺れは、小さく相関のあるもの(1/f 型、SD 10〜20ms まで)にとどめる。
   - ずれを誇張すると、かえって評価が下がる。
   - 型は、自由に使える Groove MIDI Dataset(CC BY 4.0)から作れる。
4. **音作りで一番足りないのは、内蔵シンセの変調(LFO・エンベロープの自由な割り当て)と、音源の重ね(レイヤー)。**
   エフェクトでは、次のものが足りない。
   - 上下同時に掛かるマルチバンド圧縮(OTT 型)
   - クリッパー
   - 曲線を選べる音量シェイパー
   - 動くフィルター
   - トランスゲート
5. **生楽器の質は、良質な無料音源(SFZ)で大きく上げられる。** ライセンスを一次情報で確かめた結果、次のものは Glaux の Release に置き直せる。
   - Karoryfer(CC0)、VSCO 2 CE(CC0)、FreePats の CC0 群
   - Greg Sullivan の E-Pianos(CC-BY)、Salamander Grand Piano(CC-BY)
   - SFZ の再生は、自前の小さなプレイヤーで足りる。
6. **効果は決まった課題(ベンチマーク)で測る。** 7 つの依頼を作らせ、自動の指標と、ブラインドの聴き比べで前後を比べる。

## 1. 現状の診断: AI が作った曲で何が起きているか

AI が作った 2 曲の中身(`project.json`)を数えた。

| 見たこと | CyberNeon(ドラムンベース、7 トラック・50 小節) | 深淵の龍(オーケストラ、18 トラック・116 小節) |
|---|---|---|
| ノートが 16 分の格子ちょうどにある割合 | 95〜100%(全トラック) | 67〜100%(打楽器・ハープ以外は 100%) |
| オートメーション | **0 本** | **0 本** |
| ピッチカーブ | 0 | 0 |
| 1 音の中での強弱の変化 | 表す手段が無い | 表す手段が無い(弦・金管の伸ばしがベロシティ 1 つで固定) |
| ベロシティの散らばり(標準偏差) | 6〜19 | 4〜22 |
| 奏法 | パームミュート・アクセント・ベンドを少し | ビブラートを少し。レガートは 0 |

原因は 5 つある。

1. **道具が使われない。** 手引き(`get_guide`)に「いつ・どう使うか」の段取りが薄い。
   また、ビルドアップ 1 つでも、フィルタの点を十数個、正しい tick で書く必要がある。
2. **タイミングが機械的。** 人間らしい揺れを 1 音ずつ書くのは現実的でない。
   今あるのは、全体を一律にハネさせる `swing_notes` だけ。
3. **ロングトーンが動かない。** 伸ばしている音の途中で強弱を変える手段が無い。
4. **作曲の土台は AI の暗算頼み。** コードの積み方・声部のつながり・楽器の音域を、MIDI 番号の足し算で書いている。
   LLM は和音・スケールの扱いが弱いことが報告されている(Kruspe 2024)。
5. **音色の幅が頭打ち。** 内蔵シンセに自由な変調が無い。1 トラックに 1 つの音源しか置けない。
   生楽器は GM の SoundFont の質が上限。

## 2. 基本の方針

調査から導いた、道具と進め方の設計の原則。

| 原則 | 中身 | 根拠 |
|---|---|---|
| **意図で呼べる道具** | AI は「何をしたいか」を記号と少数の数値で渡し、音程の計算・点の並べ方・揺らし方は道具が行う | Logic Session Players(complexity・intensity・fills・follow)、Live 12 の MIDI Tools、Anthropic の道具設計の指針(ミスしにくい引数、ワークフロー単位の統合) |
| **決定的** | 乱数を使う道具は、呼ぶ側が `seed` を渡す。道具は絶対値の `Command` に展開する | Glaux の原則(コマンドは決定的・絶対値) |
| **人に近い書き方** | 位置は「小節:拍」、音は音名、様式は名前で渡す。tick の計算を AI にさせない | poka-yoke(Anthropic "Building effective agents") |
| **計画を先に** | 曲の計画書を作ってから書く。計画書は構成・小節数・区間ごとの盛り上がり 0〜10・各区間の役割・オートメーションの意図 | ComposerX、ByteComposer、MuseCoco(属性を中間に置くと制御の精度が約 20% 上がる)、Loop Copilot(中央の属性表で一貫性を保つ) |
| **批評してから完了** | 機械的すぎる・平板すぎる・破綻しているを数値で返す道具を作り、直してから報告させる | Evaluator-Optimizer(Anthropic)、ComposerX のレビュアー役 |
| **大きな単位で組む** | クリップを作り、変形し、区間 × トラックに並べる | TOMI(電子音楽の全曲構造で一貫性が高い)、ABC の反復記号 |

## 3. 調査の結果

### 3.1 AI が音楽を作る研究と製品

**研究(記号 = 楽譜での作曲)**

| システム | 要点 |
|---|---|
| ChatMusician(2024) | ABC 記譜で学習。ABC は MIDI の約 38% のトークンで済み、反復記号で構造を短く書ける |
| ComposerX(2024) | GPT-4 で 6 役(リーダー・旋律・和声・楽器・レビュアー・編曲)。単体の GPT-4 の失敗を報告: 表現の微妙さの欠如、指示の翻訳失敗、音域の逸脱、声部の縦のずれ、終止が無い |
| ByteComposer(2024) | 構想分析 → 草稿 → 自己評価と修正 → 選別 |
| MuseCoco(2023) | テキスト → 属性(楽器・リズムの密度・音域・調・テンポ)→ 音楽。属性を間に置くと制御の精度が約 20% 上がる |
| Loop Copilot(2023) | 曲の属性を「中央の表」に保ち、修正をまたいで一貫性を保つ |
| TOMI(2025) | クリップ × 区間 × トラック × 変形の 4 次元で全曲を組み、REAPER に組み込み。**Glaux に最も近い** |
| NotaGen(2025) | 人手の評価なしの選好学習(CLaMP-DPO)で音楽性を上げる |

**失敗の型**(ComposerX、Kruspe 2024 など): 表情が無い・構造が無い・和音やスケールを誤る・音域の逸脱・終止が無い。
Glaux の症状(機械的・平板)は、このうち「表情」と「構造」に当たる。

**製品の設計**

| 製品 | 出している操作 |
|---|---|
| Logic Pro Session Players | ベースは 8 人の奏者、複雑さ・強さ、スライド・ミュート・デッドノート・ピックアップ、コードトラックに追従。鍵盤は 4 様式、ブロックから拡張したボイシングまで。Chord ID で既存の音からコードを検出 |
| Ableton Live 12 の MIDI Tools | 生成: Rhythm(Steps・Density・Accent)、Seed、Shape、Stacks(コードの在庫を JSON で持つ)、Euclidean(Steps・Density・Rotation)。変形: Arpeggiate(18 様式)、Connect、Ornament(フラム・装飾音の確率)、Recombine(次元ごとにシャッフル・ミラー・ローテート)、Strum、Span、Time Warp、Chop、Velocity Shaper、Quantize(量)。ノートごとの確率・ベロシティの揺れ・Humanize |
| Magenta Studio の Groove | 格子どおりのドラムに、学習したタイミングと強弱を付ける(GrooVAE) |

**教訓**: 製品は「様式(選ぶ)+ 2〜4 本の連続した量 + 追従先(コードやリズム)」に引数を絞っている。
これは LLM の道具の引数にそのまま使える。Live 12 の変形は、機械的な打ち込みを直す後処理にも当たる。

### 3.2 グルーブと演奏の表情

**スウィング**
- MPC(Roger Linn)方式では、8 分の中の 2 つ目の 16 分だけを遅らせる。50% = ストレート、66% = 3 連。
- 50〜70% の間に良い所がある。90 BPM では 66% より 62% の方が緩く感じる。
- ストレートな 16 分には **54%** を掛けると、スウィングに聞こえないまま硬さが取れる。
- Logic の 16 分スウィングは 50 / 54 / 58 / 62 / 66 / 71%。Glaux の `swing_notes`(0.5〜0.8)は同じ目盛り。
- 初期ファンクの実測では、16 分のスウィング比は 1.07:1〜1.8:1(0.517〜0.643)で、3 連には届かない。

**楽器ごとのずれ(ポケット)**
- J Dilla 型は、キックが拍の上、スネアがわずかに後ろ、ハットがわずかに前。
- 同じずれを曲全体で毎回繰り返す。ランダムではなく、固定した型。

**DAW のグルーブ機能**(Ableton の Groove Pool)

| 項目 | 中身 |
|---|---|
| Base | 測る単位 |
| Quantize | 先に格子へ寄せる量 |
| Timing | 型の効き |
| Random | 声部ごとに別の乱れ |
| Velocity | −100〜+100 |
| Global Amount | 最大 130% |
| Extract / Commit | クリップから型を取り出す / ノートに書き込む |

**ドラムマシンの条件付きの発音**(Elektron)
- 確率で鳴らす。
- A:B(B 回のうち A 回目に鳴らす)。
- 直前の結果・隣のトラックに従う。
- フィルの間だけ鳴らす。

**研究**

| 研究 | 知見 |
|---|---|
| Hennig ら 2011 | 人間のずれは長距離の相関(1/f 型)を持つ。σ 10ms の 1/f の揺れは、白色の揺れより有意に好まれた |
| GrooVAE(2019) | 表拍は遅れ気味、裏拍は早め。学習した人間化は本物と区別されなかった |
| Senn ら 2016・2018 | 熟練者のずれは、完全なクオンタイズと同じくらい評価される。**2 倍に誇張すると評価が下がる**。シンコペーションと密度は小さく効き、残りのずれ自体には効果が無い |

→ **系統的な型(楽器 × 拍の位置のずれと強弱)を主に、小さな相関のある揺れを補助に**使う。

**Groove MIDI Dataset(CC BY 4.0)を実際に集計した値**(4/4 のビート。値は参考)

| ジャンル | スネアのバックビートの遅れ | ハットの強弱(4 分 / 8 分の裏 / 16 分の裏) | スネアのうちゴーストの割合 / 強さ |
|---|---|---|---|
| ロック | +2.7ms | 100 / 66 / 55 | 16% / 36 |
| ファンク | +5.6ms | 82 / 49 / 37 | 55% / 33 |
| ヒップホップ | +5.5ms | 118 / 66 / 42 | 23% / 31 |
| ソウル | +2.8ms | 78 / 78 / 41 | 44% / 20 |
| ポップ | 0.0ms | 127 / 25 / 42 | 27% / 33 |

- ハットのずれは、隣どうしの相関が 0.49〜0.61 あった。
- 小節の平均のずれの揺れ(SD 10〜14ms)と、小節内の揺れ(9〜11ms)がほぼ同じ大きさ。

**ノートごとの表情**
- CLAP のノート表現は 7 種: 音量(0〜4)、パン、音程(±120 半音)、ビブラート、表情、明るさ、圧力。
- Glaux の `pitch_curve` は音程に当たる。残りも同じ形で足せる。

**オートメーションの定石**
- ビルドアップ: スネアの連打を細かくしていく、シンセの音量を上げる、ドロップ前に 1 小節の無音(Wikipedia「Drop」)。
- 次の値は出典の無い経験則。
  - ビルドは 8〜16 小節、ハイパスを数百 Hz まで上げる、直前にキックとベースを抜く。
  - サイドチェインの下げ幅は 3〜12dB。

### 3.3 作曲・編曲

**和声の道具**

| 製品 | 要点 |
|---|---|
| Scaler 3 | 自動ボイスリーディング。ドロップ・ギター・音域指定のボイシング。代理・転回・拡張。転調の提案。演奏の型(Motions)。コードの検出 |
| Captain Plugins | ローマ数字の進行をジャンルで絞る。ベースがコードに自動で追従 |
| Cthulhu | コードの在庫 150 以上。タブごとに長さの違うアルペジエータ(ポリメトリック) |

どれも「進行 × ボイシング × 演奏の型」を分けている。

**ボイスリーディングは決まった手順で解ける**
- 理論: Tymoczko(2006)。良いつなぎは、声部が独立し、移動が短く、声部が交差しない。移動量は各声部の半音差の和で測る。
- 実装の手本:
  - music21 の figured bass の規則(BSD): 交差の禁止、上声間 12 半音以内、連続 5 度・8 度の禁止など
  - tonal の voicing(MIT): 辞書 + 音域 + つなぎの評価関数
- 手順:
  1. 候補を列挙する。3 度・7 度は必須、5 度は省略可、拡張音は任意。音域・声部数・様式で絞る。
  2. 1 つの和音の制約を掛ける。上声間 12 半音以内、低音域の密集を避ける、3 度を重ねない。
  3. つなぎの損失を定める。移動量 + トップノートの動き + 連続 5 度・8 度 + 交差。
  4. **動的計画法(Viterbi)で進行全体を最適化する**。同点は辞書順にして決定的にする。

**ジャンルの語彙**
- 洋楽ポップ: I–V–vi–IV、♭VII の終止、セカンダリードミナント、下行するベース。
- J-POP: 王道進行 IV△7–V7–iii7–vi、丸サ進行 IV△7–III7–vi7–v7–I7。
- トランス: 短調、アルペジオ、スーパーソウ、125〜150 BPM。
- ディープハウス: 拡張和音、Rhodes、110〜125 BPM。
- ファンク: 9th・11th 付きの属七、1〜2 和音のヴァンプ、1 拍目の強調、16 分のシンコペーション。
- フューチャーベース: 130〜175 BPM、フィルタの揺れ、コードのアルペジオ。
- 次のものは出典が見つからなかったので初期値として扱う: sus・add9 のスタブ、ハウスの m7・m9 の裏拍スタブ、ローファイの maj7・m9・13 とスウィング 55〜62%。

**ベースの型**: ルートの 8 分、裏拍(トランス)、オクターブ(ディスコ・ファンク)、808 の伸ばし + グライド(トラップ)、
トレシーロ E(3,8)、ウォーキング、1 音のシンコペーション。

**旋律**
- サビは「高い音・伸ばす音・リフレイン」(亀田誠治。Wikipedia「サビ」)。
- トランスのフックは、ブレイクの前に単純化した形で予告される。

**構成**
- 4 / 8 / 16 / 32 小節の単位で組む。
- EDM: 山 → ビートを抜いたブレイク → 再構築 → 最後の山。スネアロールで予告し、ドロップの前に 1 小節の無音。
- 劇的な弧: 提示 → 上昇 → 頂点(音の密度が急に増える)→ 下降 → 結末。
- 減算のアレンジ: 先に全部を埋めてから抜いて区間を作る。
- ポップス: Verse は約 8 小節。VCVC / VCVCBC。
- J-POP: A メロ・B メロ・サビ、頭サビ、C メロ、大サビ、落ちサビ、ラスサビ。
- 盛り上がりの目安は、同時に鳴るトラック数・1 小節の打点の密度・音域の広さから求める。
- つなぎの素材(ライザー・インパクト・逆再生のシンバル・スネアロール・フィル・フィルタスイープ)は、区間の境目の 1〜2 小節前に置く。ロールは 2〜8 小節前から。

**リズム**
- ユークリッドリズム E(k, n)(Toussaint 2005)。E(3,8) はトレシーロ、E(5,8) はシンキージョ。回転を引数にする。
- 確率・条件付きの発音・ラチェット・ポリメーターは、`seed` 付きで決定的に作れる。
- ジャンルの型:

| ジャンル | テンポ | 型 |
|---|---|---|
| ハウス | 115〜130 | 4 つ打ち、2・4 拍にクラップ、裏拍のオープンハット |
| テクノ・トランス | 120〜140 | 4 つ打ち |
| ダブステップ | 135〜145 | ハーフタイム |
| ドラムンベース | 160〜180 | ブレイクビーツ。Amen は音でなく打点の並びとして持つ |
| ヒップホップ | 60〜100 | ブームバップ |
| トラップ | 約 140 | ハットの 2 分割・3 分割、808 |
| 2-step | 約 130 | 4 つ打ちから 2・4 拍目のキックを抜く |

**楽譜を作る学習済みモデル**(同梱の可否は、重み・学習データのライセンスで決まる)

| モデル | 重みのライセンス | 評価 |
|---|---|---|
| skytnt/midi-model | Apache-2.0、0.2B、ONNX 付き | **最有力**(Rust の推論 tract で動かせる見込み) |
| Composer's Assistant 2 | コードは MIT。許諾済みの MIDI だけで学習 | 重みの条件は未確認 |
| Anticipatory Music Transformer | Apache-2.0 | 伴奏・途中の補完が得意。ただし大型版は商用音源の書き起こし約 45 万件で学習しているため、同梱の法的リスクを要検討 |
| text2midi | Apache-2.0(約 900MB) | 重い |
| MIDI-LLM | Llama 3.2 のライセンス | 同梱に不向き |
| MIDI-GPT | 重みが非商用 | 不可 |

音声そのものを作るモデル(MusicGen・Stable Audio など)は、重みのライセンスと、
「すべての編集がコマンドで取り消せる」設計の両面から採らない。

### 3.4 音作り

**モダンな電子音・ポップの音で効く要素**
- LFO のテンポ同期(1/32〜8 小節、付点・3 連)とリトリガー
- フィルターエンベロープの量(± 両方向)とキーへの追従
- ユニゾン(声数・デチューン・広がり・中央と外側の比・位相の乱数)
- ウェーブテーブル位置の変調とワープ
- サブ、ノイズ
- シンセの中のドライブ
- 変調ごとの曲線と、別の変調源による量の制御

Surge XT・Vital(どちらも GPL-3.0 なので設計の参考だけにとどめる)と、Serum 2・Phase Plant を比べた。

**提案する変調の設計**(内蔵シンセ 3 種で共通)

| 変調源 | 内容 |
|---|---|
| `lfo1`・`lfo2` | 形: sine / triangle / saw / square / S&H / smooth random。速さ: Hz かテンポ同期。位相、free / retrigger / 1 回だけ、遅れ・立ち上がり、単極 / 両極、声ごと |
| `env2`・`env3` | DAHDSR + 曲線 |
| 演奏情報 | ベロシティ、キー、ノートごとの乱数、ノートの表情の曲線 |
| マクロ | `macro1`〜`macro4` |

- 変調のスロットは 8 本。各スロットは `{元, 先, 量, 曲線, 量を掛ける 2 つ目の元}`。
- 変調先の優先順: 音程 → 波形の位置・パルス幅・FM の深さ → カットオフ・レゾナンス・ドライブ → 音量・パン → ユニゾンのデチューン・広がり → ノイズ → LFO の速さ。
- 計算は制御レート(32 サンプルごと + 平滑化)で行い、音程と音量はサンプルごとに補間する。
- スロットは固定長の配列にして、オーディオスレッドでアロケーションしない。
- フィルターには、ドライブ付きの 4 極ラダー・コム・フォルマントを足す。ユニゾンは 1〜16 声。

**足りないエフェクトと技法**(設定値は経験則)

| エフェクト | 中身 |
|---|---|
| OTT 型の上下同時のマルチバンド圧縮 | シンセ・パッドに深さ 20〜40% |
| クリッパー | tanh・ハード・サイン折り返し、2〜8 倍のオーバーサンプリング |
| ビットクラッシュ・ダウンサンプル | — |
| 曲線を選べる音量シェイパー | Kickstart の型: 手作りの曲線 16 種、低域だけを沈める帯域指定。ベース・パッドで −6〜−12dB、戻り 100〜200ms |
| 動くフィルター | エンベロープフォロワー・同期 LFO。ビルドでハイパスを 20Hz → 1kHz |
| トランスゲート・スタッター | 16 ステップ + 平滑化 |
| ハース・M/S | 片側 5〜30ms、150Hz 以下はモノ |
| シマーリバーブ | 反響の帰りに +12 半音 |
| ゲートリバーブ | 保持 150〜300ms |
| ダッキングディレイ | 3〜6dB 沈める |
| フェイザー・フランジャー・トレモロ・オートパン | — |

**重ねの定石**
- キック: サブ 40〜60Hz + 胴 100〜200Hz + クリック 2〜5kHz
- スーパーソウ: 7 声、15〜30 セント
- ベースの帯域分け: 100〜150Hz 以下はモノのサイン、その上は歪ませて広げる

**レイヤーとマクロ**
- Ableton の Instrument Rack は、並列のチェーンごとに鍵盤とベロシティの範囲とフェードを持つ。
- マクロは最大 16 個あり、1 つで複数のつまみを最小・最大付きで動かせる。
- 提案:
  - **1 トラックに最大 4 層**。層ごとに鍵盤・ベロシティの範囲とフェード、移調、音量、パンを持つ。
  - **トラックのマクロ 8 個**。割り当ては先・最小・最大・曲線で、変調の元にもなる。
  - マクロは、AI が「明るさ」「広がり」のような意味の単位で操作する取っ手にもなる。

  - ラウンドロビン: seq_length / seq_position、lorand / hirand

- 次の段: リリース時の発音、キースイッチ、サステインペダル、クロスフェード、フィルター。
- 既存の実装:
  - sfizz(BSD-2)は C++ で、アーカイブ済み。仕様の解釈の参考にする。
  - Rust の sofiza(MIT / Apache)は参考になる。
  - nidhi(GPL)・xsynth(LGPL)は写せない。
- → `glaux-dsp` に**自前のパーサ**を書き、読み込みはオーディオスレッドの外で行う。

**DSP の参考資料**(コードの流用はライセンスを確かめてから)

| 分類 | 資料 |

| 関数ごとに違うもの | Faust のライブラリ(GPL の関数がある) |
| **写せないもの** | Surge XT・Vital・CHOW Tape・nidhi・Hydrogen |

### 3.6 評価のしかた

**記号の指標**
- MusPy: スケール内の音の割合・音高の偏り・空の拍の割合・グルーブの一貫性・同時発音数など。
- MGEval。
- 反復構造の圧縮率(COSIATEC)。
- Frechet Music Distance。

**音の指標**
- FAD はサンプル数と埋め込みに左右される。
- CLAP の値はテキストとの一致で、音楽性ではない。

**人の評価**
- 少人数なら、絶対評価より**対比較**が安定する。
- 「全部格子どおり」の版を目印(アンカー)として混ぜると、評価者の感度を確かめられる。

### A. 曲の骨格を作る道具

**自動で測るもの**(1 回ごとに記録)

**聴いた評価**
- 前後の版をブラインドで対比較する。
- 観点は 4 つ(グルーブ / 展開 / 和声・旋律 / 音の質)で、それぞれ A / B / 同等で答える。

- 時々「全部格子どおり」の版を混ぜる。
- 1 週間後に 2 本を聴き直して、判断の一貫性を確かめる。

## 6. 進め方(案)

電子音楽・ポップス・グルーブを先に深める。各段階の終わりにベンチマークで前後を比べる。
